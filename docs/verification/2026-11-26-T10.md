# T10 완료 조건 검증

두 예제에서 신청·조회를 한 번씩 실행한 뒤 회원 화면과 같은 `gateway.snapshot`으로 첫 기록 시각과 기능 이름 두 개를 읽었다. 첫 실행에서 드러난 기능 등록 오류와 수정은 아래 C2에 기록했다. 실험은 로컬 Supabase Auth·PostgREST·PostgreSQL 17, release Wasm을 올린 workerd, Chrome과 가짜 알림 수신기로 진행했다.

레포 루트에서 `bash scripts/verify-local.sh`로 재현한다. [실행 환경과 예제 설정](../../examples/README.md) · [브라우저·알림 시나리오](../../scripts/t10-scenario.mjs) · [DB 판정 시나리오](../../supabase/tests/evaluate.sql)

| 조건 | 결과 | 확인 방법과 근거 |
|---|---|---|
| C1 회원 격리 | 통과 | 두 개의 실제 로컬 로그인 세션에서 각자의 앱 목록을 조회하고 상대 앱의 S4 snapshot이 거절되는지 확인했다. PostgREST에서 각 세션의 자기 앱·5분 요약·문제는 1행 이상, 상대 회원은 모두 0행이었다. 직접 SQL 권한은 `ownership.sql`로 검사했다. |
| C2 첫 기록·이름표 | 로컬 통과 | 서버 메모리 앱과 localStorage 앱에 같은 연결 절차를 적용했다. Chrome에서 신청 수 1건을 확인한 뒤 양쪽 모두 `first_record_at`, POST ‘독서 모임 신청’, GET ‘신청 수 조회’를 확인했다. 처음에는 이름표만 도착했다. PostgREST의 safeupdate가 기능 정원 설정의 조건 없는 UPDATE를 거절해 수집이 503이었다. 새 마이그레이션 `20261126000000`에서 단일 설정 행을 지정한 뒤 통과했다. |
| C3 쓰기 전용 키 | 통과 | `deep_results_enforce_server_source`에서 공개 키의 서버 출처 결과를 버린다. HTTP에서 타 앱의 `app_id`를 명시한 묶음은 400, 공개 수집 키의 회원 API 조회는 거부됐다. 기존 Worker는 타 앱 지정 필드를 무시하고 원래 앱에 저장했다. 명시한 경우 묶음 자체를 거부하도록 수정했다. |
| C4 수집 금지 항목 | 통과(시험표 범위) | `shared_sanitize_vectors`, `sanitize_vectors.sql`, `sanitize-vectors.test.ts`와 실제 저장 경로를 검사했다. 오류 예시의 시험 이메일은 DB에서 이미 `[가림]`이었고 DB 예시와 S7 요청문에 시험 이메일·본문·쿼리 표식이 없었다. `masks_identifiers_and_private_text_before_rpc`는 키가 섞인 버전도 저장 RPC 전에 가리는지 확인한다. |
| C5 64 KiB·100건 | 사람 필요 | 정확히 65,536바이트인 100건 묶음 두 개가 각각 202, accepted 100, dropped 0이었다. Mac 로컬 HTTP 왕복은 10.61 ms와 10.92 ms로 DB 저장까지 포함한다. Cloudflare 대시보드에서 요청 CPU를 실측해야 10 ms 조건을 판정할 수 있다. |
| C6 문제 열림·중복 억제 | 통과 | `evaluate.sql`과 `evaluate_boundaries.sql`에서 정확히 20%, 평소 속도 2배, 10건 중 절반 미확인으로 각 문제를 열고 재판정 때 새 이벤트 0개를 확인했다. HTTP 시나리오에서는 앱별 100건 중 20건 실패를 넣어 두 번 판정했고 가짜 수신 메일은 총 2통이었다. |
| C7 업데이트 확인 | 통과 | `evaluate.sql`과 `incident_verification.sql`에서 사용 없음, 4건 성공 대기, 5번째 연속 성공을 확인했다. 실제 수집 경로에서도 두 앱의 새 버전 `repaired`로 5건씩 성공을 보내 해결 상태·버전과 회원당 해결 메일 1통을 확인했다. `monitor.test.tsx`가 화면 문구를 검사한다. |
| C8 학습 전후 | 통과 | `evaluate.sql`은 과거 시각의 성공 29건에서 p50이 null이고 관측 범위가 77~77 ms임을 확인한다. 3일 경계 후 30건에서 p50을 얻었다. `evaluate_auto.sql`은 3일 전 성공 81건에도 p50이 null임을 검사한다. `monitor.test.tsx`는 학습 전 ‘지금까지 4건’ 표시를 검사한다. |
| C9 Slack·메일 | 로컬 통과 | 실제 Worker의 OAuth 시작→가짜 코드 교환→Vault 연결→시험 알림을 거쳤다. 가짜 HTTP 수신기에서 시험 문구 1건을 확인했다. 같은 수신기가 각각 404, 410을 반환하자 양쪽 모두 연결 끊김 상태가 되고 다음 판정에서 해당 로그인 이메일로 시험 문구 1통만 도착했다. 세 번째 판정에서도 추가 발송 0건이었다. |
| C10 보관 | 통과 | `ingest.sql`, `daily_retention.sql`, `evaluate_delivery.sql`에서 7일 지난 5분 요약→시간별, 30일 지난 시간별→한국 날짜별, 하루 요약 1년, 재실행 중복 방지, 오래된 시도·오류 예시·종결 기록 정리를 검사했다. |
| C11 비밀값 | 제출 브랜치 통과 | CI와 같은 Gitleaks 8.30.1 `git --redact --no-banner --log-opts=HEAD`에서 검출 0건. 로컬의 모든 브랜치 이력을 포함한 별도 검사에서는 제출 브랜치 조상에 없는 `7641eee`의 예전 SQL 시험값 두 건이 stripe-access-token으로 분류됐다. |
| C12 제출물 | 파일 검사 통과, 내용 보완 필요 | `bash scripts/check-deliverables.sh` 출력 ‘제출 산출물 확인 완료’. T11 항목은 아래에 열거했다. |
| C13 회원 탈퇴 | 실패(제품 화면) | 로컬 Auth 관리 API로 두 시험 회원을 삭제했을 때 각 앱·요약·문제·키·알림 설정이 0행이었다. 캐시된 키로 즉시 재전송한 응답은 401이었다. 현재 회원 웹에는 본인 탈퇴 요청, 응답 끊김 뒤 10초 간격 확인, 2분 뒤 재시도 화면이 없다. |
| C14 요청문·출력 안전 | 실패(일부 제품 화면) | 요청문과 표시 함수 회귀는 통과했다. S10·S11 사용자 동작이 없어 ⑯~⑱·⑳의 전체 제품 경로를 검증할 수 없다. 아래 사례별 근거를 참조한다. |

### C14 사례별 근거

| 사례 | 검사와 결과 |
|---|---|
| ①~⑤ | `issue-prompt.test.ts`, `deep.test.tsx`가 키 가림, 버전 격리, 유니코드 정규화, 두 줄에 나뉜 지시 감지, 정상 오류 기본 포함을 검사했다. |
| ⑥~⑧ | `monitor.test.tsx`의 S7 기본 경고 선택, `onboarding.test.tsx`의 현재 앱 키·재복사·직접 선택, `prompt-safety.test.ts`의 전문 일치가 통과했다. ⑦의 앱 전환은 현재 연결 화면에서 검증했다. 별도 S10 화면은 없다. |
| ⑨~⑫ | `issue-prompt.test.ts`의 첫 요청·다시 요청·악화 분기와 5개 정상 진단 문구에서 강함/약함 및 데이터 블록 경계를 확인했다. |
| ⑬~⑮ | `monitor.test.tsx`, `display.test.ts`, `onboarding.test.tsx`, `security.test.ts`에서 기능 행·상세·이름표와 형식이 틀린 버전의 안전 표시를 확인했다. |
| ⑯ | 앱 카드·휴대폰 머리말·PC 메뉴는 `onboarding.test.tsx`에서 통과했다. S11 알림 요약·앱 삭제 화면까지 이어지는 경로는 없다. |
| ⑰·⑱·⑳ | `display.test.ts`의 전각 이름 정규화와 로그인 이메일 원문 보존은 통과했다. S10의 보이는 앱 이름 입력과 S11 탈퇴 이메일 확인 단추는 제품에서 검사할 수 없다. |
| ⑲ | `t10-gallery.mjs`가 실제 시안 갤러리를 로컬 DOM에서 열어 목록·제목·설명에 합성 키가 가려지고 태그가 글자로 보이는지 검사했다. |

명세 6.3에서는 강한 지시 문구를 기본 복사에서 제외하며, 사용자가 ‘그대로 복사’를 고르면 **정제한 데이터 블록 안**에 표시한다. 지시 문구 자체까지 DB와 모든 복사본에서 삭제한다는 T10 지시문의 더 강한 조건은 충족하지 않는다. 개인정보·키의 가림과 지시 문장의 격리는 서로 다른 시험으로 확인했다.
