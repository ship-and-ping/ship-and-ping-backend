# T10 완료 조건 검증

두 예제에서 신청·조회를 한 번씩 실행한 뒤 회원 화면과 같은 `gateway.snapshot`으로 첫 기록 시각과 기능 이름 두 개를 읽었다. 첫 실행에서 드러난 기능 등록 오류와 수정은 아래 C2에 기록했다. 실험은 로컬 Supabase Auth·PostgREST·PostgreSQL 17, release Wasm을 올린 workerd, Chrome과 가짜 알림 수신기로 진행했다.

레포 루트에서 `bash scripts/verify-local.sh`로 재현한다. [실행 환경과 예제 설정](../../examples/README.md) · [브라우저·알림 시나리오](../../scripts/t10-scenario.mjs) · [DB 판정 시나리오](../../supabase/tests/evaluate.sql)

명세 6.3에서는 강한 지시 문구를 기본 복사에서 제외하며, 사용자가 ‘그대로 복사’를 고르면 **정제한 데이터 블록 안**에 표시한다. 지시 문구 자체까지 DB와 모든 복사본에서 삭제한다는 T10 지시문의 더 강한 조건은 충족하지 않는다. 개인정보·키의 가림과 지시 문장의 격리는 서로 다른 시험으로 확인했다.

### T21 교차 검수 후 C13·C14 재검증

- **C13 통과.** 로컬 workerd HTTP 검사에서 Auth 관리자 삭제의 502와 504는 결과 불명, 404는 완료로 처리했다. 서버 설정 누락과 앱 삭제 실패에서는 503을 확인했다. 웹은 결과 불명일 때 10초마다 계정을 조회했다. 2분이 지나도 완료를 확인할 수 없으면 다시 시도할 수 있었다. 재시도에서 받은 401은 Auth의 사용자 없음 응답으로 완료를 확정하거나, 로그인 화면에서 탈퇴가 이미 끝났을 수 있다고 안내했다.
- **C14 통과.** 가려진 기능 이름은 새 이름을 입력할 때까지 저장할 수 없었다. 앱 삭제 실패 후 확인 입력은 잠긴 채 유지됐고 키보드 초점은 다시 시도로 이동했다. 탈퇴 실패 뒤에도 회원 메뉴에서 로그아웃하고 로그인 화면의 안내를 확인했다.
- 웹 테스트 187건, Rust 테스트 19건, release Wasm HTTP 테스트 1건, pgTAP 374건이 통과했다. 키 폐기 pgTAP 6건에는 소유권과 다른 앱의 키 거부, 다음 수집의 PT401, 재호출 시 최초 폐기 시각 보존이 포함된다. 두 회원의 로컬 통합 시나리오에서 Auth 삭제 실패 후 재시도와 Vault 비밀 삭제까지 확인했다.
- 탈퇴 제한은 Worker 인스턴스마다 로그인한 회원별로 30초에 두 번이다. 이 변경으로 추가할 운영 마이그레이션은 없다. PR 전체의 적용 대상은 `20261126100000_revoke_app_key.sql`이다.
