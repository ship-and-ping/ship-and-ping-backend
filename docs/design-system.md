# 쉽앤핑 디자인 시스템

React 구현자(T5·T7·T8)는 이 문서의 CSS 변수 이름과 부품 이름을 그대로 쓴다. 값의 원본은 [`tokens.css`](design/final/src/tokens.css)이고 이 문서와 같다. 시안에서는 `.sp` 요소에 토큰을 두었지만, 앱에서는 `:root`에 두고 어두운 모드는 `[data-theme="dark"]`(기본값은 `prefers-color-scheme`을 따름)로 바꾼다.

## 0. 방향 한 줄

**화면마다 지금 가장 중요한 한 문장을 쉽앤핑 양이 퍼플 카드에서 말하고, 숫자는 그보다 크게.** 나머지(목록·입력·설정)는 조용하고 단정하게. 양은 맨 위 카드에서만 말한다(대화형 배치 아님).

| 사용자 결정 (2026-11-25, 사용자 말) | 반영 |
|---|---|
| "C가 좋아보이긴네" | 시안 C 구조 그대로: 큰 문장 카드, Noto Sans KR 한 글꼴, 큰 숫자, 줄 목록 |
| "C로 하되 양 캐릭터는 B처럼" | 큰 문장 카드에만 양 아바타(36px) + 말풍선 꼬리, 해결 때 민트 고리 한 번 |
| 섞는 정도 "1: 가볍게 (추천)" | Jua 글꼴 없음, 말풍선 대화 배치 없음, 다른 화면·목록은 C 그대로 |

### 1.3 상태 색 3가지

상태는 **세 가지뿐**이고, 늘 **색 + 모양이 다른 아이콘 + 글자**를 함께 쓴다(색만으로 구분 금지).

| 상태 | 뜻 | 아이콘 | 카드 안 글자·그래픽 | 밝은 바탕 글자 | 옅은 바탕(`-soft`) |
|---|---|---|---|---|---|
| 괜찮아요 | 기록이 오고 **열린 문제가 없음**. 평소 속도를 익히는 중, 해결됐어요, 잠잠해졌어요, 문제 아님으로 닫음도 여기 | 동그라미 + 체크 | `--sp-ok` `#76E7C4` 민트(로고 'i' 점) | `--sp-ok-ink` `#0B6B50` (어두운 `#76E7C4`) | `#DDF8EF` / `rgba(118,231,196,.12)` |
| 문제 있어요 | **열린 문제가 있음**(실패·느려짐·결과 미확인 급증). 새 버전 대기·업데이트 후 첫 사용 대기·확인 중도 해결 판정 전이라 여기. 슬랙 연결 끊김처럼 사용자가 고쳐야 하는 설정 문제 | 세모 + 느낌표 | `--sp-bad` `#FF8A65` 산호 | `--sp-bad-ink` `#B3261E` (어두운 `#FF8A65`) | `#FDE7E4` / `rgba(255,138,101,.12)` |
| 기록을 기다려요 | **기록이 아직 하나도 없음**(첫 기록 전, 연결 전, 한 번도 안 쓰인 기능, 깊게 보기 첫 결과 전) | 시계 | `--sp-wait` `#CFC5E8` | `--sp-wait-ink` `#5D5673` (어두운 `#B8AED0`) | `#EEEBF3` / `rgba(184,174,208,.12)` |

**한 가지 규칙으로 정한다(D3)**: 열린 문제가 있으면 문제 있어요, 기록이 하나도 없으면 기록을 기다려요, 나머지는 괜찮아요. 상태 표시의 글자만 상황에 맞게 바꾼다("해결됐어요", "잠잠해졌어요", "첫 결과를 기다려요"). 상태가 아닌 것에는 상태 색을 쓰지 않는다.
- 이름 없는 기능, "기타" 줄, 숨긴 기능: 상태가 아니라 보조 글자색(`--sp-ink-2`) 아이콘.
- 깊게 보기 결과 4가지(성공·실패·중단·결과 미확인)는 상태가 아니라 결과 종류다(4.12). 성공 `--sp-ok-ink`, 실패 `--sp-bad-ink`, 중단 `--sp-ink-2`(사용자가 그만둔 것이라 문제 아님), 결과 미확인 `--sp-wait-ink`.
- 큰 문장 카드의 큰 숫자 색: 문제 값은 `--sp-bad`, 해결·도착 값은 `--sp-ok`, 비교 기준(평소)은 `--sp-hero-ink-2`, **아직 결론이 아닌 진행 숫자**("3 / 5건")는 `--sp-hero-ink`(흰색, `.sp-cmp .now`).
- 민트 채움 위 글자는 `--sp-on-ok` `#13372B`.
- 문제 색을 빨강이 아닌 산호로 정한 이유: 퍼플 카드 위에서 6.9:1로 읽히면서 "고장" 같은 공포감을 덜 준다. 밝은 바탕에서는 더 진한 `#B3261E`로 바꿔 AA를 지킨다.

## 4. 부품

클래스 이름은 시안 코드 그대로이고, React에서는 같은 이름의 컴포넌트로 만든다(예: `.sp-say` → `<Say>`).

### 4.1 큰 문장 카드 + 양 `sp-say` (`<Say>`)
- 구조: 양 아바타 `.sp-av`(36×36, 모서리 10px, 장식이라 `alt=""`) → 그 아래 카드 `.sp-hero`. 카드 왼쪽 위 모서리는 6px로 뾰족하고, 위로 작은 꼬리(`::before`, 16×10 삼각형)가 아바타를 가리켜 **양이 이 문장을 말하는 것처럼** 보인다.
- 카드 안 순서: ① 상태 표시 + 시각(`.meta`) ② 큰 문장 `.sp-headline` ③ 큰 숫자 비교 `.sp-cmp`(있을 때) ④ 보조 문장 `.hsub` ⑤ 단추 `.sp-hbtn`(있을 때, 하나만).
- 화면마다 **하나만**, 맨 위에. 문장은 상태 문장 사전([사용자 흐름 5장](monitoring-service-ux.md))의 문장을 그대로 쓴다.
- PC: `.sp-hero.pc` — 왼쪽 문장·단추, 오른쪽 큰 숫자.
- 접근성: `<section aria-label="쉽앤핑이 알려 드려요">`. 큰 숫자 비교는 `role="img" aria-label="평소 1.1초, 최근 30분 3.4초"`로 한 문장으로 읽힌다.
- 큰 숫자가 없는 경우(평소 속도 전): 숫자 대신 "지금까지 7건, 0.9~2.1초" 문장.

### 4.2 기능 행 `sp-frow`
- 상태 아이콘(20px) · 기능 이름(굵기 500) + 보조 줄("사용 132건, 실패 0건") · 오른쪽 최근 보통 시간 + "평소 1.1초".
- 문제 있는 행은 이름도 `--sp-bad-ink`. 정렬은 문제 있는 기능 먼저, 그다음 최근 24시간 사용 많은 순.
- 높이 최소 56px. **행 전체가 하나의 링크**(`<li><a class="sp-frow" href="…/features/:id">`)라 Tab으로 닿고 Enter로 기능 상세(S6)가 열린다. 오른쪽 끝에 `›` 아이콘. 초점 테두리는 행 전체를 감싼다. 깊게 보는 기능 행은 "깊게 보기" 꼬리표 + 결과 4가지 요약 줄, 누르면 깊게 보기 결과 화면.
- 오른쪽 값은 좁거나 글자가 크면 이름 아래로 내려간다(`flex-wrap`).
- **개수 규칙**: "기능 N개"라고 쓴 곳 아래의 목록은 정확히 N줄. 이름 없는 기능·"기타"·숨긴 기능은 세지 않고 따로 제목(`.sp-h3`)을 달아 아래에 모은다. 예: "기능 8개"(8줄) + "이름 없는 기능 1개".

### 4.3 버튼 `sp-btn`
| 종류 | 클래스 | 쓰는 곳 |
|---|---|---|
| 기본 | `.sp-btn` | 화면의 주 행동 하나 |
| 테두리 | `.sp-btn.line` | 보조 행동 |
| 글자 | `.sp-btn.text` | 덜 중요한 행동(문제 아님으로 닫기, 연결 끊기) |
| 위험 | `.sp-btn.danger` | 폐기, 삭제 |
| 카드 안 | `.sp-hbtn` | 큰 문장 카드 안의 행동 |
- 높이 48px 이상(카드 안 52px). 글자가 길면 줄을 바꾸고 높이가 늘어난다(고정 높이 금지).
- 상태: 기본 / 누름(`scale(.97)`, 0.16초) / 초점(3px 테두리) / 비활성(`aria-disabled="true"`, 회색 바탕, 이유를 바로 옆 글로) / 처리 중(`aria-busy="true"`, 회전 표시 + "등록하는 중", 다시 눌리지 않음).
- 이름은 결과를 말한다: "등록하고 연결 요청 받기", "이 이름으로 지켜보기", "AI에 보낼 내용 복사". "확인"·"제출"만 쓰지 않는다.

### 4.4 상태 표시(칩) `sp-status`
- 누르지 않는 표시라 `<span>`(단추처럼 보이지 않게, 그림자·hover 없음). 아이콘 15px + 글자 14px 굵게, 알약 모양, 한 줄 유지(`nowrap`).
- 밝은 바탕: `-soft` 바탕 + `-ink` 글자. 큰 문장 카드 안: 바탕 없이 1.5px 테두리 + 카드 안 상태 색.
- 상태가 바뀌는 순간(첫 기록, 해결)은 `sp-swap`으로 겹쳐 바꾼다(5장).

### 4.5 복사 버튼 `sp-copy`
- 묶음 `.sp-copyblock` = 단추 `.sp-btn.sp-copy` + 직접 선택 상자 `.sp-copy-manual`(평소 숨김) + [보낼 내용 미리 보기]. React에서는 `<CopyBlock kind="connect|check|deep|ai|again">`.
- **복사 결과를 확인한 뒤에만 안내한다**(D3). 순서: `navigator.clipboard.writeText` → 거절되면 예전 방식(`execCommand('copy')`) → 그래도 안 되면 실패. 누른 뒤 결과가 올 때까지 `aria-busy`로 중복 누름을 막는다.
  1. 기본: "AI에 보낼 내용 복사"
  2. 성공: `data-state="done"` 민트 채움 + "복사했어요" 2.6초, 화면 읽기에 "복사했어요. 코딩 AI 대화창에 붙여넣으세요". 이 동안 다시 눌러도 동작하지 않음.
  3. 실패(자동 복사 막힘): "복사했어요"를 띄우지 않는다. `data-state="fail"` 단추는 "다시 복사"(테두리 단추), 바로 아래에 띠 "자동 복사가 막혔어요. 아래 상자를 누르면 전부 선택돼요" + 전문 상자 `.sp-pre`(`user-select: all`, `tabindex="0"`). 상자를 누르거나 Tab으로 들어오면 전부 선택되고, 실패 직후 초점이 상자로 옮겨 간다. 화면 읽기에도 같은 내용을 알린다.
- **미리 보기는 요청문 전문**(기능명세서 6.1 연결 요청, S4 확인 요청, 6.2 깊게 보기 추가 요청, 6.3 AI에 보낼 내용). 첫 연결(S4 ①)과 깊게 보기 추가(S8)는 무엇을 보내는지 읽고 복사하도록 미리 보기를 펼쳐 둔다. 긴 전문은 높이 280px 안에서 스크롤(키보드로 초점 가능).
- 키가 들어간 요청문(연결 요청, 깊게 보기 추가) 아래에는 "다른 사람에게 보내지 마세요". 화면에 보이는 미리 보기에서는 키 뒷부분을 가리고, 복사할 때만 실제 키를 넣는다.

### 4.6 입력 `sp-field`
- 이름표는 칸 위에 늘 보인다(칸 안 흐린 글씨를 이름표로 쓰지 않음). 선택 칸은 "(선택)".
- 예시·안내는 이름표와 칸 사이 또는 칸 아래 `.help`, `aria-describedby`로 연결.
- 오류는 칸 바로 아래 `.err`(아이콘 + 무엇을 어떻게 고칠지), 칸에 `aria-invalid="true"`, `role="alert"`.
- 칸 높이 48px 이상, 글자 16px(휴대폰 확대 방지), 테두리 `--sp-line-strong`.
- 켜기·끄기는 `sp-switch`(`role="switch" aria-checked`), 52×32px.
- **확인 입력**(앱 삭제, 회원 탈퇴): 칸은 **비어 있게 시작**하고, 적은 값이 기준(앱 이름, 로그인 이메일)과 **정확히 같을 때만** 위험 단추가 눌린다(`aria-disabled`를 입력마다 다시 계산). 지우면 다시 비활성. 진행 중·실패 화면에서는 적은 값을 잠근 채 남긴다.

### 4.7 띠 알림 `sp-banner`
- 한쪽 색 줄 대신 **전체 테두리 + 옅은 바탕 + 앞 아이콘**. `.warn`(문제 색, `role="alert"`) / `.info`(기다려요 색, `role="status"`).
- 문장 + 다음 행동 하나(`.act` 밑줄 글자 단추). 예: "하루 동안 기록이 없어요. 사용자가 없었거나 연결이 끊겼을 수 있어요. [연결 확인하는 법 보기]", "알림을 받을 곳이 없어요 [알림 설정]".

### 4.8 빈 화면 `sp-empty`
- 점선 테두리 상자: 굵은 한 줄(지금 상태) + 이유 + 다음 행동 단추. "아무것도 없어요"로 끝내지 않는다.
- 화면 전체가 비었으면 큰 문장 카드가 빈 상태를 말한다(예: S5 "첫 기록을 기다리고 있어요" + [연결 단계 다시 보기]).

### 4.9 로딩 스켈레톤 `sp-skel`
- 실제 내용과 **같은 자리·같은 높이**의 옅은 막대(`.line` 14px, `.title` 30px, `.num` 52px, `.btn` 52px). 내용이 와도 화면이 밀리지 않는다.
- 0.3초 안에 끝나면 보여 주지 않는다(깜빡임 방지). 감싼 요소에 `aria-busy="true"`와 "…불러오는 중" 이름.
- 1.4초 주기로 밝기만 바뀐다. 동작 줄이기면 멈춤.
- 진행 상황을 아는 경우(업데이트 후 확인)는 스켈레톤 대신 **실제 숫자**("3건 성공, 2건 더 확인할게요").

### 4.10 오류 안내 `sp-error`
- 옅은 문제 색 바탕 + 전체 테두리 + 세모 아이콘, `role="alert"`.
- 굵은 한 줄 "무엇이 안 됐는지" + 한 줄 "어떻게 하면 되는지/무엇이 안전한지"("고친 이름은 그대로 있어요") + 다시 하기 단추.
- 불러오기 실패 때 마지막으로 본 내용을 지우지 않고 남긴다. **흐리게 하지 않는다**(D3: 투명도 0.7이면 보조 글자가 3.31:1로 AA 미달). 대신 목록 위에 시계 아이콘 + "14:20에 불러온 내용"을 쓴다. 오류 코드는 [자세히] 안에만.

### 4.12 깊게 보기 결과 `sp-results` (D3)
- 2열 칸 4개, 늘 같은 순서: 성공(체크) · 실패(세모) · 중단(나가는 화살표) · 결과 미확인(물음표). 칸마다 아이콘 + 이름 + 큰 건수(30px) + 한 줄 뜻.
- 색은 1.3의 결과 종류 규칙. 글자 200%에서는 1열.
- 쓰는 곳: S8 첫 결과 도착, 깊게 보는 기능 화면. S5 목록 행에는 한 줄 요약("사용 88건: 성공 84, 실패 1, 중단 3, 결과 미확인 0").

### 4.13 그래프와 기간 고르기 `sp-bars`, `sp-linechart`, `sp-seg` (D3)
- 기간 고르기 `.sp-seg`: [24시간] [7일] 두 칸, `aria-pressed`, 칸 높이 44px. 바꾸면 같은 자리의 그래프만 바뀐다(움직임 없음).
- 사용·실패 막대 `.sp-bars`: 칸마다 위 사용(`--sp-chart`), 아래 실패(`--sp-bad-ink`)를 2px 틈을 두고 쌓는다. 실패가 있으면 최소 4% 높이로 보이게. 막대 묶음에 `role="img"`와 한 문장 설명, 아래에 범례 `.sp-legend`(색 칸 + 글자)와 시작·끝 시각.
- 보통 걸린 시간 선 `.sp-linechart`: 실선(`--sp-ink`) + 평소 속도 점선(`--sp-ink-2`). 선 두께 2.5px, 그림 위에 숫자를 쓰지 않고 바로 위 문장에 "점선이 평소 속도 1.1초, 지금 3.4초"로 쓴다.
- 7일 보기는 하루 단위, 24시간 보기는 2시간 단위.

### 4.14 글자 200% 메뉴 `sp-menu` (D3)
- 글자를 크게 하면 머리말의 알림·설정 아이콘(`.not-big`)을 숨기고 [메뉴] 단추(`.only-big`, `aria-expanded`) 하나로 모은다.
- 펼친 목록: 알림 설정 · 앱 설정 · 깊게 볼 기능 추가 · 내 앱 목록 · 내 계정, 한 줄 56px. Esc 또는 [메뉴]로 닫는다.

## 5. 움직임

| 언제 | 무엇이 | 어떻게 | 값 |
|---|---|---|---|
| 첫 기록 도착 (S4) | 상태 표시 "첫 기록을 기다려요" → "기록이 도착했어요", 큰 문장 바뀜 | 이전 것 투명도 0, 새 것이 6px 아래에서 떠오름 | `--sp-dur-swap` 200ms, `--sp-dur-rise` 280ms, `--sp-ease-out` |
| 해결 (S7) | 상태 표시 → "해결됐어요", 막대가 왼쪽부터 채워짐, "/ 15건 평소 속도" 나타남, **양 둘레 민트 고리 한 번** | `transform: scaleX`, 고리는 `scale(.92→1.2)` + 투명도 | `--sp-dur-fill` 700ms, `--sp-dur-ring` 700ms(막대 다음) |
| 단추 누름 | 단추 | `scale(.97)` | `--sp-dur-press` 160ms |
| 스위치 | 손잡이 | `translateX` | 200ms |
| 로딩 | 스켈레톤 | 밝기만 | 1.4초 주기 |
| 처리 중 | "…하는 중" 회전 표시 | `rotate` | 0.7초 주기 |
| 기간 바꾸기, 메뉴 여닫기 | 그래프·목록 | 움직이지 않고 바로 바뀜 | — |

이 장이 움직임과 동작 줄이기의 **유일한 기준**이다. [사용자 흐름 6장](monitoring-service-ux.md)은 원칙만 적고 이 장을 따른다(D3 재검수에서 두 문서를 맞춤).

규칙
- 움직이는 것은 `transform`·`opacity`뿐. 매일 보는 목록·표·숫자는 움직이지 않는다. **숫자를 세어 올리지 않는다.**
- 반복되는 움직임은 로딩 표시에만. 고리는 한 번만.
- `ease-in` 금지, 강한 ease-out(`cubic-bezier(.23,1,.32,1)`).
- **동작 줄이기**(`prefers-reduced-motion: reduce`) — 한 곳(`components.css` 맨 아래 미디어 쿼리)에서만 처리한다(D3 정리):
  | 대상 | 평소 | 동작 줄이기 |
  |---|---|---|
  | 상태·문장 바뀜(`sp-swap`) | 이전 것 0.2초 사라짐 + 새 것 6px 떠오름 | 둘 다 0.15초 투명도만 |
  | 해결 막대·"/ 15건" | 왼쪽부터 채움 | 0.15초 투명도만 |
  | 민트 고리 | 한 번 퍼짐 | 없음 |
  | 단추 누름 | `scale(.97)` | 없음(`transform: none`) |
  | 스위치 | 손잡이 미끄러짐 | 바로 바뀜 |
  | 스켈레톤 | 밝기 1.4초 주기 | 멈춤 |
  | 회전 표시("등록하는 중") | 0.7초 회전 | 1.6초로 느리게 유지(진행 중임을 알리는 필수 표시라 멈추지 않음) |
  바뀐 결과(글자·숫자·색)는 두 경우 모두 똑같이 보인다. React에서는 CSS 미디어 쿼리를 쓰고 JS 타이머로 움직임을 따로 돌리지 않는다.

## 6. 큰 글자(200%)에서의 배치

기기 글자 크기를 200%로 키워도 내용이 잘리거나 가로로 넘치지 않게 한다. ([화면 모음](design/final/index.html)의 "S5 큰 글자(200%)")

| 부품 | 배치 변화 |
|---|---|
| 큰 숫자 비교 | 가로 → 세로로 쌓고 화살표를 아래 방향으로 |
| 기능 행 | 오른쪽 시간 값을 이름 아래로 내림 |
| 머리말 | 보조 아이콘 단추(알림·설정)는 숨기고 **[메뉴] 단추 하나**로 모은다(4.14). 제목은 줄 바꿈 |
| 깊게 보기 결과 | 2열 → 1열 |
| 단추·입력 | 고정 높이 대신 최소 높이 + 안쪽 여백이라 글자만큼 커짐 |
| 큰 문장 | 자르지 않고 줄 바꿈(`keep-all`). 말줄임(…) 금지 |
| 상태 표시 | 한 줄 유지, 공간이 모자라면 옆 시각 글자가 다음 줄로 |

구현: 크기는 rem, 줄 간격은 단위 없는 숫자, 높이는 `min-height`. `overflow: hidden`으로 글자를 숨기지 않는다.

글자 크기 설정 경로: 앱 안에 따로 글자 크기 설정은 두지 않고 **기기·브라우저 설정을 따른다**(휴대폰 글자 크기, 브라우저 확대). 그래서 rem 기준으로 만들고, 200%에서 머리말 단추가 [메뉴]로 바뀌는 경로를 화면 모음의 "S5 큰 글자: 메뉴 연 모습"에 그렸다.

## 10. 화면 너비와 PC 배치 (D4)

쉽앤핑은 **웹페이지**이고 기준 화면은 **PC 브라우저**다(사용자 지적 2026-11-25: "근데 이거 웹페이지인데 앱만 너무 만든거 아니야?"). 시안은 창 1440×900 기준으로 그리고 1280에서도 확인한다. 휴대폰 화면은 같은 내용의 반응형 배치다. 코드: [`desk.css`](design/final/src/desk.css), [`desk.js`](design/final/src/desk.js).

### 10.1 너비 기준

| 이름 | 화면 너비 | 배치 |
|---|---|---|
| PC | **1024px 이상** | 왼쪽 메뉴(248px) + 오른쪽 본문(가운데 정렬, 최대 폭 1080px, 좌우 여백 40px) |
| 태블릿 | 640~1023px | 왼쪽 메뉴를 접고 머리말에 [메뉴] 단추(4.14와 같은 펼침 목록). 본문 한 열, 좌우 여백 24px |
| 휴대폰 | 640px 미만 | 휴대폰 화면 그대로(머리말 + 한 열, 좌우 16px) |

- 화면 모음에서 창 너비를 1440·1280(PC), 1023·640(태블릿), 639(휴대폰)로 바꿔 경계값마다 배치가 바뀌는 것을 볼 수 있다. 태블릿은 위쪽 줄 [메뉴] 단추(`aria-expanded`)가 왼쪽 메뉴를 위에서 펼치고 닫으며(Esc로 닫힘), `.sp-cols`·`.sp-grid3`·PC 큰 문장 카드는 모두 한 열이 된다.
- 기준은 CSS 너비이므로 브라우저 확대도 같이 적용된다. PC 창 1440을 200%로 키우면 실제 폭 720 → 태블릿 배치(화면 모음 "S5 큰 글자" PC 보기).
- 1280 창: 본문 폭 = 1280 − 248 − 80 = 952px. 최대 폭(1080)에 닿지 않아 본문이 창에 맞춰 줄어들고, 두 열 그리드는 그대로 유지된다.

### 10.2 왼쪽 메뉴 `sp-side`

| 순서 | 항목 | 비고 |
|---|---|---|
| 1 | 워드마크 + "쉽앤핑" | 누르면 내 앱 |
| 2 | 내 앱 | 앱을 고르면 바로 아래에 **앱 안 메뉴**가 펼쳐진다: 앱 이름(작게) → 홈 · 기능 · 문제(열린 문제 수) · 설정 |
| 3 | 알림 설정 | 앱마다 정하므로 본문 맨 위에 앱 고르기(`.sp-seg` 링크) |
| 4 | 내 계정 | |
| 맨 아래 | 로그아웃 | 확인 없이 바로, S1으로 |

- **앱 문맥**: 앱 안 메뉴의 앱 이름, 각 항목이 가는 화면, "문제" 옆 숫자는 **지금 고른 앱**의 것이다. 열린 문제가 0개면 숫자를 쓰지 않는다. 알림 설정으로 가면 그 앱이 미리 골라져 있다.
- 한 줄 높이 44px, 아이콘 20px + 글자. 지금 화면은 `aria-current="page"` + 옅은 바탕 + 왼쪽 3px 진한 줄 + 굵게(색만으로 구분하지 않음).
- 큰 문장 카드와 양 아바타는 **본문 맨 위**(제목 바로 아래)에 둔다. 왼쪽 메뉴에는 양을 넣지 않는다(브랜드는 워드마크).

### 10.3 본문과 그리드

| 클래스 | 쓰는 곳 | 규칙 |
|---|---|---|
| `.sp-wrap` | 본문 전체 | 최대 폭 1080px, 구역 사이 24px. 맨 위는 경로(작게) + 제목(`--sp-text-xl`) |
| `.sp-cols` | 할 일 + 옆 안내 | 주 열 `1fr` + 옆 열 360px, 사이 32px. 옆 열은 스크롤해도 따라온다(sticky). 예: 요청문 미리 보기 + 연결 단계(S4), 기능 목록 + 고치는 순서(S5), 그래프 + 버전 비교(S6), 복사 + 지금까지 흐름(S7) |
| `.sp-cols.even` | 같은 무게의 두 묶음 | 두 열 같은 폭(S1 소개+로그인, S11) |
| `.sp-grid3` | 같은 종류 카드 여러 개 | 3열, 사이 16px(S2 앱 카드) |
| `.sp-body.narrow` | 입력 화면 | 최대 폭 720px(S3·S8·S9·S10·탈퇴). 입력 칸이 너무 길어지지 않게 |
| `.sp-panel` | 옆 열·묶음 | 바탕 `--sp-surface`, 1px 선, 모서리 12px, 안쪽 20px |

- 큰 문장 카드는 PC에서 `.sp-hero.pc`(왼쪽 문장·단추, 오른쪽 큰 숫자).
- 태블릿 이하에서는 `.sp-cols`가 한 열이 되고 옆 열은 주 열 **아래**로 간다(읽는 순서 그대로).

### 10.4 넓은 화면의 표·목록

- 기능 목록은 PC에서 열을 맞춘다: 상태 아이콘 28px | 이름 + 보조 줄 | 지금·평소 120px(오른쪽 정렬) | `›` 28px. 행 전체가 링크, 마우스를 올리면 옅은 바탕.
- 표(`sp-table`)는 숫자 열 오른쪽 정렬, 표 폭은 담긴 구역 폭을 따른다(옆 열 360px 안에서도 4열이 들어가게 글자 14px).
- 한 줄 글은 80자를 넘기지 않는다(설명 문단 `max-width: 60ch`). 넓은 화면이라고 문단을 끝까지 늘이지 않는다.
- 요청문 미리 보기는 PC에서 높이 520px까지 펼쳐 보이고(휴대폰 280px), 그 옆에 단계 안내를 둔다.

### 10.5 키보드 이동 순서 (PC)

1. 왼쪽 메뉴: 워드마크 → 내 앱 → (앱 안 메뉴: 홈 → 기능 → 문제 → 설정) → 알림 설정 → 내 계정 → 로그아웃
2. 본문: 제목 영역(알림 설정의 앱 고르기) → 큰 문장 카드 안 단추 → 주 열(위→아래) → 옆 열(위→아래)
- 화면 순서와 HTML 순서를 같게 둔다(CSS로 순서를 바꾸지 않음). 옆 열이 sticky여도 순서는 주 열 다음.
- **화면이 바뀌면 초점을 새 화면의 제목(h1, `tabindex="-1"`)으로 옮긴다.** 초점이 문서 맨 앞(BODY)으로 돌아가 메뉴부터 다시 지나가지 않게 한다. 화면 읽기도 새 제목부터 읽는다. 처음 페이지를 열 때는 옮기지 않는다.
- 태블릿의 [메뉴]를 열면 첫 메뉴 항목으로 초점이 가고, Esc로 닫으면 [메뉴] 단추로 돌아온다.
- [자세히] 안의 주소·오류 원문은 PC에서도 펼치기 전에는 보이지 않는다(넓은 화면이라고 미리 펼치지 않음).
- 구현 때 본문 맨 앞으로 건너뛰는 "본문으로 가기" 링크를 메뉴보다 먼저 둔다(시안에는 그리지 않음).

### 10.6 S0 소개 페이지

- 로그인 전 첫 화면. 맨 위 줄(워드마크 · [로그인] · [시작하기]) + 가운데 최대 폭 1120px 구역들: 한 문장 소개 → 문제 공감 → 하는 일 세 가지 → 연결 세 단계 → 실제 화면 예시 → 알림 예시 → 무료 베타 안내.
- 큰 제목 46px(휴대폰 32px), 구역 제목 28px(휴대폰 24px). 같은 글꼴(Noto Sans KR) 한 가지.
- 양은 맨 위 예시 카드 한 곳에서만 말한다. 아래 "실제 화면 예시"의 큰 문장 카드는 양 아바타를 빼고 그린다(`K.say({ noAv: true })`). 실제 화면 예시는 "예시 데이터"라고 밝힌다.
- 로그인 화면(S1)에는 소개로 돌아가는 링크("쉽앤핑 소개로 돌아가기", PC·휴대폰 모두)를 둔다.
- 가격, 성과 숫자, "최고·유일" 같은 말, 지어낸 후기는 쓰지 않는다.
