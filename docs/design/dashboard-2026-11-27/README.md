# 트루바 대시보드 시안 선택

**B 상태 요약을 추천한다.** 앱 홈 첫 문장에서 열린 문제 수와 기능 이름을 읽고, 같은 카드에서 문제를 열 수 있다. 휴대폰 알림을 눌러 문제 화면에 바로 들어온 사람은 첫 화면에서 상태를 확인하고 조사 요청문을 복사할 수 있다. [전후 비교 열기](index.html) · [B 시안 열기](option-b/index.html)

비교 페이지에서 시안, 화면, 너비, 테마를 고른다. 앱 홈·기능 상세·문제·알림 설정의 현재 화면과 선택한 시안이 나란히 열린다. 390px에서는 ‘기능 상세 · 그래프 펼침’을 고르면 접은 화면 뒤의 차트까지 볼 수 있다. 각 시안에서 기능 이름을 누르면 해당 기능의 기록으로 이동한다.

| 추천 순위 | 방향과 달라지는 화면 | 주요 디자인 값 | 구현 난이도와 위험 |
|---|---|---|---|
| 1 · [B 상태 요약](option-b/index.html) | 홈은 문제 수 → 이유 → 문제 열기 순서다. 아래에는 오늘 일어난 일과 앱 요약을 둔다. 상세에서는 같은 상태 카드 아래에 건수와 시간을 나란히 두고, 휴대폰에서는 하나씩 펼쳐 읽는다. | 상태 카드 반경 22px, PC 안쪽 여백 32×38px, 양 영역 154px. 두 차트 사이 26px. | 중간. 열린 문제 수와 과거 실패 건수를 구분해야 한다. 해결된 문제까지 열린 수에 넣으면 첫 문장이 틀린다. |
| 2 · [A 기록 중심](option-a/index.html) | PC 왼쪽 메뉴, 홈의 문제 → 기능 목록 순서를 살린다. 기능 상세의 두 차트를 위아래로 읽고 같은 시각을 눈금으로 찾는다. | PC 메뉴 208px, 주 콘텐츠 최대 1032px, 상태 제목 28px. 차트 표시 영역 높이 185px. | 낮음. 차트 수정 범위가 작다. 두 번째 그래프를 보려면 PC에서도 아래로 이동해야 할 수 있다. |
| 3 · [C 기능 비교](option-c/index.html) | 홈에서 문제를 한 줄로 읽고 기능별 사용량·실패·24시간 미니 막대를 비교한다. 상세에서는 숫자 세 개를 차트 앞에 둔다. | PC 기능 행 72px, 미니 막대 높이 36px, 공통 축 0~50건. 휴대폰은 기능명 아래 한 줄에 28px 높이로 배치한다. | 중간~높음. 기능마다 축을 따로 잡으면 드문 기록이 많은 사용처럼 보인다. 공통 축에서는 작은 막대를 읽기 어려워 정확한 건수도 함께 표시한다. |

## 현재 화면에서 확인한 순서

| 위치 | 현재 동작 | 시안에 반영한 판단 |
|---|---|---|
| 앱 홈·기능 목록 | 앱 홈은 이미 열린 문제를 첫 문장에 둔다. 문제 있는 기능도 목록 앞으로 정렬한다. 버전 띠와 문제 목록을 지난 뒤 기능별 건수에 닿는다. | A와 B의 목록은 문제 있는 기능을 먼저 둔다. C는 열린 문제를 표 위에 고정하고 표 안에서는 사용 많은 순으로 비교한다. |
| 기능 상세 | 제목 바로 아래 사용·실패 합계가 나온다. 사용 축은 0과 최대값뿐이고 보통 시간 요약만 최근 한 시간을 조회한다. 캡처에서 같은 화면에 ‘최근 1시간 기록 없음’과 과거 측정점 6개가 보였다. | 상태와 문제로 가는 행동을 그래프 앞에 둔다. 점선 간격과 단위를 표시하고, 시간 설명과 그래프가 같은 조회 기간을 사용한다. |
| 알림에서 연 문제 | 상태와 감지 수치는 이미 위에 있다. 요청문 복사는 시간 순서와 업데이트 확인 뒤에 있다. | 상단 카드와 휴대폰 하단에 같은 조사 요청문 복사 버튼을 둔다. 요청문을 확인하고 싶은 사람은 본문에서 전문을 읽을 수 있다. |
| 알림 설정 | 현재 웹에서는 앱을 선택한 뒤 슬랙, 이메일 순서로 나온다. | 새 사용자 결정에 따라 앱 푸시를 기본, 메일을 대비용, 슬랙을 팀용 선택으로 표시했다. 홈 화면에 추가하는 안내를 펼치거나 예시 알림을 눌러 문제 화면을 열 수 있다. |

기준 화면은 커밋 `089a0bc`의 React 웹을 Windows에서 로컬 실행해 캡처했다. S5·S6·S7의 흐름과 기존 기능을 확인한 근거는 [화면 명세](../../monitoring-service-ux.md), [읽기 QA](../qa/2026-11-27-readability.md), [45개 패턴 점검](../qa/2026-11-26-ui-patterns.md), [디자인 시스템](../../design-system.md)이다. 시안은 대시보드 판단과 복사 동선을 다룬다. 기존 버전 비교·느림 기준 저장·문제 닫기 등 운영 기능은 실제 웹의 비교 전 화면에서 확인할 수 있다.

## 예시 데이터와 그래프 읽기

- 운영에서 보고받은 값은 트루바 ‘기타’의 **11월 27일 14:15~14:20 실패 30건**이다. 이 수치를 고정하고 성공 수·속도·다른 기능·이전 날짜를 예시로 구성했다. 운영 DB를 직접 조회한 결과와 구분해 모든 시안에 예시 표시와 기준 시각을 넣었다. [공통 데이터](fixture.js)
- 11월 26일 18:00~27일 18:00, 한국 시간 기준이다. ‘기타’는 72건 중 30건 실패했다. 14:00~15:00 막대는 아래 성공 20건과 위 실패 30건을 합친 50건이다. 10:00~11:00의 보통 시간은 5초이고, 그다음 구간은 1초다. 17:00~18:00에는 이 기능의 측정이 없다. 점이 없는 시간은 선으로 연결하지 않는다.
- 24시간은 1시간씩, 7일은 시작 시각부터 24시간씩 묶는다. 툴팁과 표에 시작·끝 시각을 표시한다. 기간별 보통 시간은 예시 측정 건수로 가중한 중앙값이다. 건수와 초를 각각의 축에 표시한다.
- 건수 축은 0·10·20·30·40·50건, 시간 축은 0~5초다. 바닥선 위 1px 점선 5줄, 막대 위쪽 반경 최대 4px, 이웃 막대 최소 간격 2px, 쌓은 값 사이 표면색 2px를 쓴다. 보통 시간은 2px 선과 지름 10px 점, 표면색 2px 테두리를 쓴다. 실패는 빗금과 범례로 표시한다. 단일 시간 계열은 제목이 범례 역할을 한다.
- 마우스를 올리거나 터치하면 해당 구간의 값을 읽을 수 있다. 키보드는 좌우·Home·End로 이동하고 Escape로 툴팁을 닫는다. 선 그래프에는 선택한 구간의 세로선이 뜬다. ‘표로 보기’는 24행 또는 7행을 보여 준다.

## 스킬과 대비

`ui-ux-pro-max`를 먼저 실행했다. `monitoring dashboard accessible status` 디자인 시스템 검색에서 확인 시각·상태 표시·키보드 초점 규칙을, `sparse time series stacked bar` 차트 검색에서 시간별 선·색 외 구분·표 제공 규칙을 가져왔다. React 검색에서는 초점 관리와 역할·이름을 통한 확인 방식을 참고했다. 기존 한국어 글꼴과 퍼플 브랜드 계열을 사용했다. `frontend-design`으로 A의 기록 읽기, B의 상태 판단, C의 기능 비교에 각각 다른 정보 순서를 부여했다. 독립 실행 가능한 `impeccable` 스킬은 로컬 설치 경로에서 발견되지 않아 기존 QA와 직접 렌더링으로 평가했다.

섹션 제목은 본문 잉크색, 눈금과 설명은 보조 글자색이다. 밝은 모드와 어두운 모드에 별도 색을 지정하고, 렌더링된 CSS 토큰의 sRGB 상대 휘도로 아래 대비를 계산했다.

## 휴대폰과 검증 범위

- 390px에서는 상태가 첫 화면에 나오고, 그래프는 처음에 접혀 있다. 상단 상태 카드의 복사 버튼과 엄지로 누르는 하단 버튼이 같은 요청문을 복사한다. 주요 하단 버튼은 최소 48px다. 7일로 바꿔도 펼친 차트가 유지된다.
- Windows Edge 로컬 렌더링으로 현재 화면 18장과 시안 54장, 총 72개의 PNG를 생성했다. 두 화면 너비와 두 테마에서 비교 페이지 선택, 가로 넘침, 이미지 로드, 실패 30건 툴팁, 시간 점 6개, 24시간·7일 표, 알림에서 문제로 이동, 복사 처리기에 전달되는 요청문을 확인했다. 휴대폰 첫 화면은 390×844px이고 펼친 차트 사진은 같은 너비의 전체 길이다. 휴대폰 너비의 브라우저 검증이며, 실기기 푸시 발송과 OS 클립보드 검사는 이번 시안 범위 밖이다.
- 현재 웹 캡처는 로컬 예시 응답을 사용한다. 시안의 앱 푸시·홈 화면 설치는 화면과 안내만 표현한다. 실제 알림 권한을 요청하거나 메시지를 발송하지 않는다.
- 재현하려면 Windows에서 잠금 파일 기준으로 `web/` 의존성을 설치한 뒤 레포 루트에서 `node docs/design/dashboard-2026-11-27/capture.mjs`를 실행한다. [캡처 및 검증 스크립트](capture.mjs)
