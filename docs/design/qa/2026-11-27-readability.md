# 읽기와 다음 행동 찾기 · T39

처음 방문한 제작자는 소개에서 가입·로그인으로, 첫 앱 등록 뒤에는 연결 요청문으로 이동한다. 다시 방문한 제작자는 내 앱에서 이름과 상태를 확인한 뒤 기능이나 문제를 열고, 필요한 경우 코딩 AI에 요청문을 보낸다. 이 흐름을 기준으로 Windows Edge에서 수정 전 화면을 연 다음 간격, 색, 아이콘, 문구, 글자 크기·굵기, 배치, 테두리·그림자, 이미지, 움직임 순으로 점검했다.

| 화면 | 무엇이 불편했나 | 어떻게 바꿨나 | 실행 확인·코드 판단 |
|---|---|---|---|
| 소개 · 실제 화면 예시 | 예시 전체와 안쪽 상태 카드에 같은 큰 그림자가 겹쳤다. 두 선택 버튼 사이 간격은 4px였다. | 바깥 그림자를 걷고 버튼 간격을 8px 토큰으로 맞췄다. 첫 소개에서 서비스 대상과 코딩 AI에 보낼 요청문을 짧게 설명한다. | Edge 전후 캡처. 예시 문제 행에서 Enter를 누르면 상세 내용이 열리고 선택 버튼에 초점이 간다. |
| 내 앱 | 카드마다 굵은 윗선과 상태가 앱 이름보다 먼저 보였다. 정상 아이콘도 상세 화면과 달랐다. | 앱 이름, 상태, 열린 문제 수, 마지막 기록 순으로 읽힌다. 윗선을 덜어내고 정상에 체크 표시를 쓴다. 화면 읽기 이름에는 상태 글자만 포함한다. | 390px 전후 캡처와 DOM 순서 확인. 앱 이름은 기존 공용 표시 함수를 거친다. |
| 앱 등록 | 설명은 필수 입력 라벨을 되풀이했고 ‘등록’만으로는 다음 단계를 알기 어려웠다. | ‘등록하면 코딩 AI에 붙여넣을 연결 요청문을 드려요’와 ‘등록하고 연결하기’로 결과를 미리 알린다. | 390px 기본·200% 글자에서 확인. 등록 한도와 키 발급 회귀 테스트 통과. |
| 깊게 볼 기능 추가 | 세 칸의 입력 조건이 긴 요청문 미리 보기와 복사 버튼 아래에 있었다. | 기능 추가 조건을 해당 버튼 바로 위에 두고 복사 버튼에는 복사 가능 시점을 남겼다. | 390px 전후 비교. 잘못된 칸의 오류 문장과 입력 관계는 DOM 속성으로 확인. |
| 로그인·가입·휴대폰 승인 | 기본 로그인과 보조 메일 링크, PC 확인 숫자와 기기 정보가 이미 구분돼 있었다. | 기존 위계와 두 자리 입력 흐름 유지. | 로그인·가입·비밀번호 찾기·재설정·승인 입력 화면 Edge 검사. 승인·거절 조건은 기존 테스트. |
| 연결·앱 홈·기능·문제 | 연결 키 경고, 최근 문제, 기능별 기록과 요청문 복사가 이미 서로 다른 구역에 있었다. | 경고와 요청문 순서, 상태 글자·색, 문제 닫기의 보조 버튼 유지. | 대기·정상·문제·해결과 조회 오류를 Edge에서 열어 검사. 키 가림·복사는 회귀 테스트. |
| 알림·앱 설정·내 계정 | 이메일 알림을 누르면 스위치와 슬랙 버튼이 같이 흐려져 어느 설정을 저장하는지 분간하기 어려웠다. 앱 삭제와 탈퇴는 이미 별도 확인을 거친다. | 이메일 카드에 요청 경과를 두었다. 삭제·탈퇴 확인 배치는 유지했다. | 키보드로 스위치를 작동한 상태를 캡처. 설정·계정 기본 화면 Edge 검사. |

본문 크기·굵기와 마스코트는 기존 토큰과 배치를 사용한다. 390px 어두운 화면에서 글자 200%와 동작 줄이기를 함께 적용했다. 검사 시점에 가로 넘침과 실행 중인 애니메이션은 발견되지 않았다. 화면 읽기 검사는 접근성 트리와 axe 기준이며 실제 보조기기 음성 낭독과 사용자 관찰은 미실시다.
