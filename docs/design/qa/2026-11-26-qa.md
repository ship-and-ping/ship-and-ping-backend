## 다시 보기

수정 후 80개 조건 모두 문서 가로 넘침 0px, axe의 WCAG 2 A·AA 및 2.1 AA 자동 검출 위반 0건이었다. 네 조건에서 Tab과 Enter로 앱 홈의 문제를 열고 복사 완료를 확인했다. 동작 줄이기 조건 20건에서는 실행 중인 애니메이션이 없었다. 웹 테스트 159개·lint·프로덕션 빌드가 통과했다.

[비교 페이지](index.html)를 브라우저에서 열고 화면과 조건을 고른다. 그림을 누르면 원본 크기로 열린다. 정지 이미지에서는 글과 배치를 비교할 수 있다. 움직임은 개발 서버에서 확인한다.

`web/`에서 `npm ci` 후 `npm run qa:shots`를 실행하면 after 이미지와 측정 결과가 갱신된다. Windows에서는 설치된 Edge, 그 밖의 기기에서는 해당 Playwright 버전에 맞는 WebKit이 필요하다. before는 기준 커밋에 같은 QA 도구를 놓고 `npm run qa:shots -- before`로 실행한다. 두 인수 모두 현재 체크아웃을 촬영한다.

## 범위와 가정

실제 브라우저는 Windows Edge다. 글자 200%는 루트 글꼴 크기로 재현했다. 네 조건을 조합해 검사했으며 모든 OS·브라우저의 조합까지 검증하지 않았다. 실제 메일·Slack·배포는 호출하지 않았다. 키보드 검증 대상은 앱 홈에서 문제를 열어 요청문을 복사하는 경로다. 실제 비전공자와 화면 읽기 프로그램을 사용한 과업 검증은 남아 있다.

공개 참고 페이지의 텍스트는 확인했다. 토스·듀오링고의 실제 스크롤과 표정 애니메이션은 열어 보지 못해 요청문 설명을 따랐다. Raycast는 제품 예시를 실제 화면처럼 제시하는 흐름을 참고했다.

### 2차 검증 결과

Edge에서 20개 화면·상태를 네 조건으로 열어 최종 캡처 80장을 저장했다. 문서의 가로 넘침과 axe 지정 규칙 위반은 각각 0건이다. 390px 기본 글자 크기에서 제목·본문·도움말·버튼 등의 실제 글자 위치를 검사했을 때 한두 한글 글자만 남은 마지막 줄은 검출되지 않았다. 동작 줄이기 20개 조건에서 실행 중인 애니메이션은 0개였다.

문제 제목 초점, 닫기 버튼 위계, 앱 홈에서 키보드로 이동해 복사 완료하기, 소개 예시 전환을 확인했다. 타임라인의 시각 요소 테스트는 수정 전 실패, 수정 후 통과했다. 웹 테스트 159개와 프로덕션 빌드·린트가 통과했고 비교 페이지에서 전후 이미지 80쌍을 오프라인으로 열었다.
