### 후보 45개의 판단

| 원문 범위 | 선택 근거 |
|---|---|
| 1–9 버튼·선택 | 1은 알림 설정의 저장 결과를 보완했다. 3·32의 성공 피드백은 기존 동작별 글자·체크로 전달한다. 4는 기능 숨기기에 있다. 8은 글자로 표시하는 메뉴와 펼침 상태로 충분하다. 9는 시스템 테마를 따른다. 2·5·6·7은 좋아요·단일 선택 설문·평점·측정 가능한 진행 작업이 있는 화면에서 검토할 수 있다. |
| 10–18 로딩 | 11·18을 적용했다. 조회 완료 시점을 알 수 없어 12·14의 퍼센트를 표시할 근거가 없다. 10·13은 기존 로딩 글자·막대와 겹친다. 15·17은 최대 세 앱 목록에 이점이 작고 16에 해당하는 업로드 흐름은 없다. |
| 19–27 입력 | 21·26은 기존 비밀번호 버튼과 기본 앱 선택기를 사용한다. 24의 오류 설명을 입력과 연결했다. 25는 두 자리 전체를 한 번에 붙여넣을 수 있고 앞자리 0을 보존하는 단일 칸을 유지한다. 19는 고정 라벨을 가릴 이유가 없고 20·22·23·27에 해당하는 검색·연속값·수량·태그 작업은 없다. |
| 28–36 피드백 | 31·32는 복사 결과와 연결 상태에 이미 있다. 29의 문제 수는 글자로 보인다. 34는 키 변경 등 기존 확인 동작을 쓴다. 28·33·35는 인라인 피드백과 상시 보이는 도움말에 비해 확인 동작을 늘린다. 30은 삭제 확인이 중요한 서비스에 맞지 않고 36은 실시간 대화가 있어야 의미가 있다. |
| 37–45 콘텐츠 | 두 화면 중 하나를 고르는 소개 예시에 39를 보완했다. 37의 별도 탭 구조 없이 선택 상태가 전달된다. 38은 긴 요청문과 기술 상세에 있다. 40·41은 내용을 숨기고 42·43은 숫자 판독을 늦출 수 있다. 44·45는 목록이 많아지거나 사용자 정렬 요구가 생길 때 검토한다. |

### 실행 범위와 제안

Windows Edge와 로컬 QA 데이터로 28개 장면을 1440px 밝게, 1280px 어둡게, 390px 밝게, 390px 어둡게·글자 200%·동작 줄이기에서 열었다. 112개 조합에서 axe의 WCAG A·AA 대상 규칙 위반과 가로 넘침이 없었다. 변경 비교는 여섯 장면 24쌍이다. 수정 전 앱 소스는 `13ed80e`이고 같은 장면·데이터·브라우저 조건을 사용했다. 수정 전 소스에 이번 QA 스크립트를 두고 `web/`에서 `npm run qa:shots -- patterns-before 0 2 4 14 26 27`, 수정 후에는 `npm run qa:shots -- patterns-after`로 재현한다.

디자인 점검표를 기존 확정 시안에 적용하고 사용자 지시에 따라 바로 수정했다. 실제 화면 읽기 프로그램의 음성, 실기기 터치, 운영 Slack·메일 전달, 다른 작업자의 교차 검수와 사용자 관찰은 확인하지 않았다. 앱 수 제한이 바뀌어 목록 탐색이 어려워지면 검색(20)을 별도 기능으로 제안한다. 현재 한도에서는 이름과 상태가 첫눈에 읽히는 카드가 우선이다.
