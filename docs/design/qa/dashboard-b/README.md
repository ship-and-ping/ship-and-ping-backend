# 대시보드 B안 실제 앱 검수

[실제 앱 전후와 3단 비교](index.html) · [1440px 비교](comparison-1440.png) · [390px 비교](comparison-390.png)

같은 트루바 예시 기록과 11월 27일 18시를 기준으로 Windows Edge에서 촬영했다. 두 너비와 두 테마에서 홈의 문제·정상·첫 기록 대기, 기능 상세, 문제 상세, 알림 설정을 확인했다. 변경 전 24장, 변경 후 28장이다. 변경 후에는 390px에서 그래프를 펼친 모습과 복사 거부 후 본문 끝의 모습도 포함한다.

| 화면 | 구현과 검증 |
|---|---|
| 앱 홈 S5 | 열린 문제 1개와 감지 당시 실패 30건을 다른 라벨로 읽는다. 최근 24시간에 보이는 기능의 사용이 1~3건이거나 버전은 있지만 사용이 0건이면 기록이 적다고 표시한다. 이는 화면 안내 기준이다. 기능별 속도와 평소 범위는 목록에서 펼쳐 본다. |
| 기능 상세 S6 | 24시간·7일 요약과 그래프의 기간을 맞췄다. 각 세로축은 최대값을 포함하는 간격으로 점선 3~5개를 표시한다. 건수 범례와 평소 속도 비교가 필요한 경우의 범례를 유지했다. |
| 문제 상세 S7 | 상단에서 상태를 확인하고 요청문을 복사한다. 390px에서는 스크롤 뒤에도 하단 복사를 사용한다. Enter로 복사한 클립보드와 미리 보기 본문이 일치하는지 확인했다. |
| 알림 S9 | 앱 푸시 ‘곧 제공’, 이메일 스위치, 선택형 슬랙 순으로 읽는다. |

첫 비교에서 390px 앱 이름이 둘째 줄로 밀리고 홈의 문제 버튼이 중복됐다. 헤더를 한 줄로 맞추고 홈 카드 버튼은 하단으로 모았다. PC에서는 단일 범례를 없앤 뒤 높이가 달라진 두 그래프의 눈금을 정렬했다.

실제 앱은 판정 당시 건수와 최초 감지 시각을 제공한다. 시안의 5분 구간을 모든 문제에 적용할 수 없어 ‘처음 감지’로 표기했다. 회원 메뉴, 버전 비교, 속도 기준 변경, 요청문 경고와 닫기 등 기존 조작을 제공하므로 일부 화면은 시안보다 길다.

웹 테스트 2,852개, 빌드, 린트와 산출물 검사를 통과했다. 점선을 실선으로 바꾼 변형에서 검출한 점선이 0개가 되어 테스트가 실패했다. 복원 후 다시 통과했다. 변경 후 24개 기본 화면에서 가로 넘침과 실행 오류를 검사하고 axe의 WCAG A·AA 규칙을 실행했다. 키보드 동작은 로컬 예시 계정으로 검증했다. 실제 회원 관찰과 실기기 화면 읽기 검수는 미실시다.

재현은 `web/`에서 `node qa/dashboard-b.mjs after`를 실행한다. 변경 전 캡처에는 기준 커밋 `879b59f`의 앱 코드와 같은 캡처 스크립트를 사용한다.
