### 알림에서 AI 요청문까지

390×844 Edge에서 예시 알림 링크와 하단 복사 버튼을 실제로 탭했다. 매회 새 브라우저 컨텍스트에서 알림 링크를 누르기 직전부터 ‘복사했어요’가 나타날 때까지 측정했다. **2탭, 중앙값 0.52초**였다. 5회 원자료는 777·482·439·521·659ms이고, 5회 모두 OS 클립보드와 미리 보기 전문이 일치했다. 앱을 고르거나 그래프를 열 필요가 없다. 이 값에는 브라우저 전환과 화면 로딩이 들어가며, 실제 사람의 읽기·반응 시간, 네트워크 푸시 배송, OS 알림 센터 지연은 측정 범위 밖이다. [복사 전](shots/issue-390-light.jpg) · [복사 완료](shots/copied-390-light.jpg)

같은 문제 주소를 로그아웃 상태로 열면 `/login`으로 바뀐다. 그 자리에서 기존 회원의 예시 세션을 복원하고 새로 고치면 `/apps`에 도착했다. 4개 폭·테마 조합에서 같았다. 앱 하나 기준 가장 짧은 복귀 경로는 인증 조작 외에 **알림 → 앱 선택 → 홈의 요청문 복사, 3탭**이다. 앱과 문제를 다시 식별하는 시간이 추가된다. 백그라운드 기기 잠금 상태의 일반 푸시에는 문제 URL이 없으므로, 이 수정은 문제 URL이 있는 메일·푸시 링크에 적용한다. [인증 필요](shots/guest-link-390-dark.jpg) · [세션 복원 뒤 도착 화면](shots/lost-link-390-dark.jpg) · [문제 URL이 있는 알림의 클릭 처리](../../../web/public/sw.js)

## 레퍼런스에서 읽은 차이

- **Grafana**의 PC Stat은 502×144, 패널 사이 8, 반경 12, 테두리 1이다. 쉽앤핑은 357×143, 간격 8, 반경 12, 테두리 1이다. 바깥 카드의 높이 차이는 1px뿐이다. 반면 휴대폰 툴팁은 Grafana 약 158×87, 쉽앤핑 149×194로 높이 차이가 107px다. 미니 차트의 선택값 배치가 발표 전 손볼 곳이다. [Stat 비교](index.html#scene=stats&width=390&theme=dark)
- **토스**와 쉽앤핑의 PC 히어로 제목은 각각 80/96px와 79.92/94.31px다. 390에서는 40/46px와 40/47.2px다. 글자 크기를 키울 근거는 작다. 소개 예시에 실제 제품의 복사 행동을 연결하는 편이 사용자 목표에 가깝다. [히어로 비교](index.html#scene=intro&width=1440&theme=light)
- **PostHog** 모바일 제품 그림은 너비 358, 반경 20이다. 쉽앤핑 모바일 예시도 너비 358, 반경 20이지만 그 안에 반경 24의 상태 카드와 실패 목록을 다시 둔다. 소개 카드 안쪽 16px와 겹겹의 테두리·그림자가 같은 사건을 두 묶음으로 보이게 한다. [예시 비교](index.html#scene=landing-preview&width=390&theme=light)
- **Plausible** 모바일 데이터 카드는 너비 358, 반경 6, 다음 카드까지 20px, 검정 10% 그림자 두 겹이다. 쉽앤핑의 문제 요약은 너비 358, 반경 24, 안쪽 22×18, 테두리 1px다. 작은 숫자의 참조값은 Plausible 19.2/28.8px, 쉽앤핑 모바일 Stat 21.6/25.92px다. 읽기 순서가 좋은 문제 카드의 모서리를 일괄 축소할 이유는 없다. [문제 비교](index.html#scene=issue&width=390&theme=light)

비교 페이지에는 26개 화면·상태별로 박스, 여백, 반경, 선, 그림자, 글자/행간을 붙였다. 캡처 속 ①은 관찰 대상의 왼쪽 위다. 현재 화면 수치는 촬영 당시 DOM에서 읽었고 레퍼런스는 11월 27일 실측이다. 폼·빈 화면은 공개 제품의 카드와 텍스트 계층을 비교했다. 같은 업무의 인증 화면끼리 비교한 자료는 없다. Grafana는 두 테마 원본이 있고 다른 세 사이트는 보관한 원본 테마로 표시한다. 기존 기록에 없는 수치는 미측정으로 표시했다. [Grafana 실측](../qa/demo-insights/README.md) · [나머지 레퍼런스와 원본 JSON](../dashboard-2026-11-27/README.md)

## 증거의 범위와 도구

- Windows Edge, DPR 1, 1440×900 및 390×844로 촬영했다. 소개·회원가입·로그인·비밀번호 찾기는 운영 공개 페이지를 익명으로 열었다. 회원 화면과 세션 복원은 같은 체크아웃의 웹을 로컬 빌드하고 기존 `web/qa/fixtures.mjs`의 예시 응답으로 격리했다. 운영 계정·비밀번호 입력은 0회다. 26장면×4조합과 확대 2장이다.
- Impeccable 실행 파일과 설치된 스킬은 이 Windows 기기에서 찾지 못했다. 공식 critique의 인지 부담·작업 기억·위계와 audit의 대비·테마·반응형 기준을 읽고 단독 수동 평가에 사용했다. 화면 점수는 이번 검토자의 평가이고 자동 detector 결과는 없다. 새 설치 없이 기존 Edge·Playwright·axe·Vite를 사용했다. [critique 기준](https://github.com/pbakaus/impeccable/blob/main/.agents/skills/impeccable/reference/critique-rubric.md) · [audit 기준](https://github.com/pbakaus/impeccable/blob/main/.agents/skills/impeccable/reference/audit.md)
- 이 기기의 `ui-ux-pro-max` 스킬과 quick-reference에서 터치 44px, 포커스 비가림, 4/8 단위 간격, 상태 피드백, 감소 모션을 적용했다. `intaeng:design` 체크리스트로 상태별 복귀 경로를 점검했다. 사용자 요청 범위에 따라 시안 제작·구현은 생략했다. 단독 검토이며 비개발자 사용성 테스트와 독립 검수는 미실시다.
