## 흔들림 원인과 변경

이전 합성 코드에서 `cameraFor`는 버튼 위치를 테이크당 한 번 읽었지만, FFmpeg의 가로 크롭 좌표에는 프레임 번호에 따른 코사인 이동을 더했다. 원본 4:2:0 영상의 크롭이 색차 격자에 맞춰져 같은 위치에 머물다가 한 번에 움직였다. 다음 테이크가 자기 시작점에서 다시 출발해 글자가 좌우로 흔들려 보였다.

기존 커밋 `8cb29e9`의 MP4에서 15.0초부터 3.8초 동안 “분석이 느려졌어요” 밝은 글자의 경계를 추적했다. 114프레임의 인접 쌍 113개 중 105개는 그대로였고, 움직인 8쌍은 한 번에 1~2px씩 왼쪽으로 갔다. 제목의 왼쪽 경계는 15px 이동했다. 같은 현상은 레이아웃이나 스크롤바가 바뀌지 않는 카드에서도 나타났다. 다음 명령의 `x1`을 비교하면 이전 MP4에서 재현할 수 있다.

```powershell
ffmpeg -hide_banner -nostats -ss 15.0 -t 3.8 -i marketing/reel-01/final/ship-and-ping-reel-01.mp4 -vf "crop=810:84:90:1076,bbox=min_val=182" -an -f null -
```

[녹화 코드](capture-utils.mjs)에서 2배율 원본의 좌표와 크기를 짝수 픽셀로 한 번만 정한 뒤 모든 프레임에 적용한다. 브라우저 창이 자리를 잡은 뒤에는 내부 화면의 배율과 위치를 고정한다. 강조 장면에서는 [같은 녹화에서 추출한 이미지](film.mjs)를 별도 레이어에서 움직인다.

## 최종 MP4 검수

최종 MP4에서 앱 정지 구간 열 곳을 2차와 같은 방법으로 측정했다. 첫 프레임의 글자·테두리 윤곽을 고르고 인접 프레임마다 가로·세로 ±2px 안에서 오차가 가장 작은 이동을 찾았다. **1,218쌍에서 최대 이동은 0px**였다. 쌍 수로 가중한 평균 밝기 차이는 **0.06546 / 255**였다. [측정 코드 및 영역 좌표](stability.mjs)

창의 첫 민트 표시 중심을 출력 프레임마다 추적했다. 진입 104프레임과 퇴장 64프레임에서 이동 방향 역전은 모두 0회였다. 프레임 간 이동량의 최대 변화는 각각 0.34px와 0.14px였다.

최종 타임라인 41장을 직접 확인했다. 10·11초는 연결 버튼, 12·13초는 복사 확인, 14·15초는 붙여넣기, 16·17초는 첫 기록이다. 18·19초의 실제 홈에서 21–23초의 큰 알림 카드로 이어진다. 24·25초, 26·27초, 28–30초에 요청문 복사 전·후와 미리 보기가 각각 이어지고, 31–33초에는 새 버전, 35·36초에는 해결 카드가 보인다. 대표 프레임 8장을 최종본에서 추출했다. 첫 검수에서 큰 카드가 양의 얼굴을 가려 양을 왼쪽으로 옮기고 카드의 폭과 위치를 다시 맞췄다.

FFmpeg로 2,424프레임을 전부 디코딩해 검은 화면·디코딩 오류·누락 타임스탬프가 모두 0개임을 확인했다. Chrome 1배속 완주는 40.41초였고 재생기가 보고한 표시 드롭은 1프레임이었다.

## 연출과 제작

[공식 양 SVG](../../docs/design/brand/sheep.svg)의 몸, 머리, 뿔, 네 다리, 눈, 털을 한 벌의 관절로 쓴다. 발을 기준으로 한 무대 좌표, 점프와 착지 자세, 부위별 회전을 분리했다. 말풍선 충돌과 종이비행기 투척에 앞서 자세를 낮추고, 머리가 먼저 움직인 뒤 털이 따라간다. 지면의 타원 그림자는 양이 뛸 때 옅어진다. [동작 타임라인](motion.js)

사용 흐름의 글자를 읽을 동안 브라우저는 정면에 둔다. 시차는 행성·언덕·지면·앞쪽 풀에 주고, 원근은 창이 들어오는 순간에만 준다. 접속 키를 다루는 연결·붙여넣기 장면은 검수한 좁은 영역만 담았다. 알림과 업데이트 화면은 넓은 실제 화면과 큰 발췌를 함께 보여 준다. 코딩 AI 창은 로고 없는 [중립 입력창](neutral.html)의 실제 녹화다. 종이비행기 투척은 전송을 표현하는 연출이다.

로컬 앱은 `13ed80e` 기준 React 화면을 Vite에서 제공한다. [데모 응답](demo.mjs)은 [앱의 검수 데이터](../../web/qa/fixtures.mjs)를 기반으로 하며 녹화 중에 연결 대기 → 첫 기록 → 느림 → 새 버전 → 해결 순으로 바꾼다. 합성은 60fps, 실제 UI 캡처는 1440 × 900 CSS 픽셀·기기 배율 2·30fps다. UI의 각 원본 프레임은 두 출력 프레임에 해당하고 양과 카메라·타이포는 60fps에서 각각 계산한다.

## 다시 만들기

Chrome, Noto Sans KR 가변 TTF, FFmpeg와 ffprobe가 설치된 환경에서 레포 루트에서 실행한다. 글꼴이 시스템 기본 위치에 없으면 같은 파일을 `marketing/reel-01/assets/NotoSansKR-VF.ttf`에 둔다.

```powershell
npm.cmd --prefix marketing/reel-01 ci --cache marketing/reel-01/.cache/npm --no-audit --no-fund --ignore-scripts
npm.cmd --prefix marketing/reel-01 run capture
npm.cmd --prefix marketing/reel-01 run render
npm.cmd --prefix marketing/reel-01 run verify
```

`raw/`와 `capture/`에 현재 판의 고정 크롭 녹화가 있으면 렌더 단계부터 시작할 수 있다. 로컬 HyperFrames 0.9.85와 내장 GSAP 3.15.0을 사용한다. 렌더러의 업데이트 확인과 텔레메트리는 꺼져 있다. 검수 명령은 프레임 타임스탬프, 검은 프레임, 음원 수, 자막 좌표, 흔들림, Chrome 전체 재생을 확인하고 대표 프레임·타임라인·측정 JSON을 만든다.
