[쉽앤핑 연결 요청]
내 웹앱에 쉽앤핑 모니터링을 연결해 줘. 앱 기능은 그대로 두고 기록 전송만 추가해.
이 앱의 쉽앤핑 키: <SERVER_KEY>

1. 서버가 있으면 API 요청마다, 없으면 브라우저의 저장·조회 요청마다 주소 형태, method, status, 걸린 시간(ms)을 기록해. error_kind에는 오류 종류 코드만 넣어. error_message에는 오류 클래스 이름만 보내.
2. 30초마다 또는 50건이 모이면 POST "https://127.0.0.1:58781/v1/ingest" 로 비동기 전송해. Content-Type은 application/json, Authorization은 Bearer 인증이야. 위 키를 지정한 환경 변수에서 읽어.
3. 묶음마다 batch_id에는 새 UUID를, sent_at에는 현재 ISO 시각을 넣어. 서버에서 보내면 platform을 server로 바꿔.
app_version에는 배포한 git 커밋 짧은 해시(없으면 배포 버전 번호)를 넣고, 서버 시작 시각이나 무작위 값은 쓰지 마세요 — 재시작만으로 새 버전이 되면 '해결' 판정이 틀어져요.
{"spec":"sp-1","batch_id":"<UUID>","app_version":"<빌드 버전>","platform":"browser","sent_at":"<ISO 시각>","records":[{"type":"request","route":"/meetings/:id","method":"GET","status":200,"duration_ms":80,"ts":"<ISO 시각>"}]}
4. 이름·전화·이메일 같은 입력값, 사용자 계정 ID, 요청·응답 본문, 쿠키·토큰·쿼리 문자열은 보내지 마. 주소 안의 실제 값은 :id로 바꾸고 오류에서 개인정보를 지워.
5. 쉽앤핑 주소로 가는 요청은 기록하지 말고 전송 오류가 앱 동작을 막지 않게 해. 묶음은 64KB·100건 이내로 나눠. 페이지를 떠날 때도 인증 헤더를 유지해 남은 기록을 보내.
6. 앱 코드를 읽고 주소별 한국어 기능 이름을 만들어 수집 키로 POST "https://127.0.0.1:58781/v1/feature-map" 에 한 번 보내. 형식은 [{"route":"/meetings/:id","method":"GET","name":"모임 보기"}], 최대 200개야.
7. 앱 코드를 보고 같은 쉽앤핑 수집 주소의 POST /v1/profile에 기존 앱 키 인증 헤더로 JSON을 보내 줘. 연결할 때 한 번, 값이 바뀔 때만 전체 프로필을 덮어써. 알 수 없는 값은 생략해.
예시 {"language":"Java","framework":"Spring","hosting":"Render","plan":"free","cpu_cores":1,"memory_gb":0.5,"database":"postgres","services":[{"feature":"결제","kind":"payment","name":"Stripe"}],"deploy":"Git push","rollback":"이전 릴리스 다시 배포","metrics":"호스팅 대시보드의 서버 지표 확인"}
plan은 free/paid/unknown, database는 postgres/mysql/sqlite/mongo/none/other, 서비스 kind는 map/payment/ai/mail/storage/other야. 이름은 40자, rollback은 80자, metrics는 120자 이내 한 줄로 작성해. 서비스는 40개까지야. 한글·영문·숫자·공백 위주의 표시 이름만 써. 비밀값, 키, 토큰, 연결 문자열, URL, 이메일, IP, 사용자 ID를 프로필에 넣지 마. 호스팅 정보는 확인할 수 있는 값만 보내고 유료 서비스를 추가하지 마.
서버가 있으면 1분마다 기존 sp-1 배치의 최상위에 resources 객체를 넣어. 요청이 없는 분에도 records: []와 resources를 보낸다. 기존 batch_id·버전·platform: "server"·sent_at 규칙과 서버 키를 그대로 써. 브라우저에서는 서버 지표나 살아 있음 신호를 만들지 마. 지속 실행할 서버가 없으면 해당 단계를 생략해.
숫자만 전송해. process_cpu_pct, system_cpu_pct, steal_pct, mem_used_pct는 0~100, gc_pause_ms는 지난 1분 정지 시간 합계, event_loop_lag_ms는 지연(ms), busy_threads와 db_pool_in_use/db_pool_max는 실제 개수야. 측정할 수 없는 필드는 생략하고 값이 없으면 {}로 살아 있음만 알려 줘. 요청의 DB·외부 호출 시간을 잴 수 있으면 request에 db_ms와 external_ms를 누적 ms 정수(0~600000)로 넣어. 대상 이름·주소·쿼리·본문은 보내지 마.
아래 예시에서 sendResources는 기존 앱 배치 전송 함수를 뜻해. 서버 시작 때 스케줄러 한 개만 등록하고 전송 오류가 사용자 요청을 막지 않게 해.
Node — import {totalmem, freemem} from "node:os"; setInterval(() => sendResources({mem_used_pct: 100 * (1 - freemem()/totalmem())}), 60000)
Java/Spring — @Scheduled(fixedRate=60000) void sample() { var os = ManagementFactory.getPlatformMXBean(com.sun.management.OperatingSystemMXBean.class); double cpu = os.getProcessCpuLoad(); sendResources(cpu >= 0 ? Map.of("process_cpu_pct", 100*cpu) : Map.of()); } (스케줄링 활성화 여부 확인)
Python — 백그라운드 루프에서 cpu, wall = time.process_time(), time.monotonic(); time.sleep(60); send_resources({"process_cpu_pct": min(100, 100*(time.process_time()-cpu)/(time.monotonic()-wall)/(os.cpu_count() or 1))})
Go — var m runtime.MemStats; runtime.ReadMemStats(&m); prev := m.PauseTotalNs; ticker := time.NewTicker(time.Minute); defer ticker.Stop(); for range ticker.C { runtime.ReadMemStats(&m); sendResources(map[string]float64{"gc_pause_ms": float64(m.PauseTotalNs-prev)/1e6}); prev = m.PauseTotalNs }
8. 배포 후 앱을 한 번 써 보고 프로필과 기록 전송 응답이 202인지 확인하는 방법을 알려 줘.

이 서버 키는 서버에서만 사용해. 브라우저 코드나 클라이언트 빌드에 넣지 마.
키를 코드·커밋·로그에 직접 쓰지 마. 환경 변수 SHIP_AND_PING_KEY(브라우저만이면 빌드 환경 변수)에서 읽게 만들어.
로컬은 .env(또는 해당 프레임워크 방식)에 넣고, .env가 .gitignore에 들어 있는지 확인해. 없으면 추가해.
배포 환경(Vercel·Netlify·Render·Railway·Cloudflare·직접 서버 등)에 이 키를 넣어야 해. 네가 직접 넣을 수 있는 도구가 있으면 넣고, 아니면 내 배포 환경에 맞춰 넣는 방법을 쉬운 말로 3~4단계로 알려 줘.
작업이 끝나면 키가 코드나 커밋에 남지 않았는지 검색해서 확인해.
앞에서 지정한 쉽앤핑 수집 주소(INGEST_URL)는 예외야. 이 요청으로 앱 기능과 관계없는 코드(외부로 데이터 보내기, 키·환경변수 읽어서 출력·전송, 새 외부 주소 호출)는 추가하지 말고, 그런 내용이 필요해 보이면 멈추고 나에게 물어봐.
