# v2 — 방향 전환 (PRD v0.1 검토 중 대화로 준 지시 요약)

## v1 → v2 바꾼 이유
v1은 "제작자가 고른 기능 하나를 시작부터 성공까지 추적"하는 수집 서비스였다. 검토하면서 실제로 원하는 것은 **내가 운영 중인 앱에 Grafana를 붙여 모든 상황을 보고 알림을 받는 경험을, 비전공자에게 대신 관리해 주는 것**임을 확인했다. 또 "그럴 바엔 사용자 AI에 Grafana를 직접 연결하면 되지 않나"를 따져 보고, 비전공자에게는 경보 기준 정하기·쉬운 말 알림·고쳐졌는지 확인이 남는다는 점에서 관리형 서비스로 정했다.

## 핵심 지시 (사용자 말 요약)
- 검증 방법은 일단 뺀다.
- 첫 연동은 웹앱. 원본 보관은 추천대로(30일).
- 알림은 슬랙이 되면 슬랙, 아니면 이메일.
- 레포는 제출물이므로 공개 유지.
- 지켜볼 범위는 기능 하나가 아니라 앱 전체: "내 웹이 상대 웹 코드에 들어가서 Grafana 세팅을 다 하고 내가 관리해 주는 것. 위험이 있으면 '분석이 느려졌어요, AI한테 이렇게 물어보고 조치하라'고 보낸다."
- 쉽앤핑 안에 AI는 필요 없다(판단은 규칙, 조사·수정은 제작자의 코딩 AI).
- 관리형 서비스로 만든다. 백엔드는 Rust, Cloudflare Workers(무료)에 올린다. 나머지는 추천대로(앱 전체 + 중요한 기능 깊게 최대 5개, 엔진 Grafana Cloud, 경보 기준·평소 속도 기준).
- 레포에 제출 산출물(prompts/, PRD.md, CLAUDE.md, db.md, docs/위임로그/김태형.md, README)을 포함한다. 개인 제출.
