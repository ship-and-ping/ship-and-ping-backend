# 쉽앤핑 T24 6차 수정 — 방식 전환: '금지 키 목록' → '허용 키 목록' (같은 브랜치·같은 PR #23)

너는 Orca 작업 에이전트(Codex)다. 브랜치 `fix/T24-sanitize-followups`(PR #23)에 커밋을 더한다. **머지 금지.**
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로. 시작 전 `git fetch origin` → `git merge origin/main`(T29 병합분).

## 왜 바꾸나 (매니저 결정, 2026-11-26)
금지 키 이름을 하나씩 추가하는 방식은 6번의 검수마다 새 키(first_name, nickname, dob, 한글 키 `이름=`, JSESSIONID, member_no, login_id …)가 빠져서 끝나지 않는다. 사용자 원칙은 **"덜 가리는 쪽보다 더 가리는 쪽"**. 그래서 오류 문구(`error_message`·`error_kind`·attempt `step`의 자유 글) 정제를 **허용 목록 방식**으로 바꾼다.

## 새 규칙 (Rust·web·DB 세 곳 동일, 공통 시험표·조합 테스트로 고정)
1. 오류 문구 안의 **모든 키-값 쌍** — `key=value`, `key: value`, `key : value`, `"key":"value"`, `'key':'value'`, `key => value`, `key -> value`, 이스케이프·이중 이스케이프, 배열·객체·숫자 값, URL 인코딩(`%3D`·`%3A`), 쿠키 `a=1; b=2` 여러 쌍 — 에서 **키가 허용 목록에 없으면 값을 `[가림]`**. 키는 영문·숫자·`_`·`-`·`.`뿐 아니라 **한글 등 모든 문자**를 키로 본다(`이름=홍길동` → `이름=[가림]`).
2. 허용 목록(진단에 필요하고 개인정보가 아닌 것, 대소문자·`_`/`-`/camelCase 무관): `status`, `status_code`, `code`, `error`, `error_code`, `type`, `kind`, `reason`, `method`, `route`, `path`(값은 기존 route 정제 — 숫자·UUID·긴 조각 `:id`, 쿼리 제거), `line`, `column`, `file`, `function`, `stack`(값은 기존 숫자·키 규칙 적용), `duration`, `duration_ms`, `timeout`, `retry`, `attempt`, `step`, `version`(값은 `mask_version`), `platform`, `feature`. 이 밖의 키는 모두 가림. 목록은 한 곳(시험표 옆 JSON 등)에서 관리해 세 구현이 같은 목록을 쓰게.
3. 키-값이 아닌 자유 글에는 기존 규칙 유지(전화·주민·외국인·카드 Luhn·이메일·키 접두·Bearer 등 고정 패턴, URL 쿼리 `?[가림]`, 경로 `:id`).
4. 헤더 형태(`Authorization: …`, `Cookie: …`, `Set-Cookie: …`)는 1번 규칙으로 자연히 가려진다 — 기존 시험표 사례가 모두 그대로 통과해야 한다(회귀 금지). 기존 금지 키 목록 코드는 1번으로 대체되면 정리.
5. **길이 상한 순서**: 원본을 먼저 2,000자로 자르고 → NFKC 등 정규화 → 다시 2,000자로 자르고 → 정제 → 명세대로 300자. 정규화로 늘어난 길이가 처리 비용을 키우지 않게.
6. **묶음 단위 벤치**: 64KB·100건 묶음(기록마다 error_message·error_kind·step 3필드, 적대적 입력 섞기)을 Rust release로 정제하는 전체 시간을 재고, 상한을 단언(CI 여유 포함, 예: 로컬 5ms 목표). 결과를 결과 문서에.
7. 기능 영향 점검: 기능 이름표·feature-map·route 비교·요청문에서 이 정제를 거치는 값이 있으면 깨지지 않는지 테스트(앱 버전은 `mask_version` 그대로).
8. 결과 문서·PR 본문: 방식 전환 이유, 허용 목록, 남은 위험(키 없는 자유 글 속 이름·주소).

## 이번에는 검수가 한 형태씩 찾아내지 않도록 **형태 전체를 한 번에** 덮는다
1. 민감한 이름 집합 S = Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-Key, Api-Key, X-Auth-Token, X-Access-Token, X-CSRF-Token, 그리고 기존 키 이름 규칙(token/key/secret/password/passwd/pwd 포함 — camelCase·PascalCase·`_`·`-` 경계)에 걸리는 모든 이름. 대소문자 무관.
2. S의 이름이 **어떤 형태로 와도** 값 전체를 가린다 — 아래 형태 표를 모두 시험표에 넣는다:
   - `Name: value` / `Name : value` / 줄 시작·중간
   - `Name=value` (쿼리·폼·쿠키 안, `&`·`;`·공백·끝까지)
   - JSON: `"Name":"value"`, `"Name" : "value"`, `'Name':'value'`, 이스케이프·이중 이스케이프, 배열 값, 객체 값, 숫자 값
   - `Name => value`, `Name -> value`, `Name, value`(로그 튜플)
   - URL 인코딩: `Name%3Dvalue`, `Name%3Avalue`
   - 쿠키 값 안의 여러 쌍: `Cookie: a=1; sid=abc; token=x` → 쿠키 헤더 값 **전체** 가림, `Set-Cookie: sid=abc; Path=/; HttpOnly` → 값 전체 가림
   - 값 스킴: Bearer·Basic·Token·ApiKey·Digest·스킴 없음
3. 소문자 합성어: `privatekey`, `accesskey`, `secretkey`, `apikey`, `clientkey`, `authkey`, `sessionkey`, `signingkey`, `encryptionkey`, `masterkey`는 명시 목록으로 가림(keyboard·monkey·hockey·turkey·whiskey·donkey 오탐 없음을 시험표로).
4. 시험표 끝에 **"형태 × 이름" 조합 표**를 생성하는 방식(예: 이름 목록 × 형태 템플릿을 테스트 코드에서 조합해 세 구현에 모두 돌리기)으로 빠짐을 줄인다 — 고정 시험표 + 조합 테스트.
