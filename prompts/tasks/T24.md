## 고칠 것 (테스트 먼저 — 공통 시험표에 사례를 추가하고 세 곳 모두 통과)
1. `token: Bearer abc` 형태에서 web/DB에 `Bearer` 뒤 값 일부가 남는 문제(이전 검수 잔여) — 세 곳 동일하게 전부 가림.
2. JSON 따옴표 자격 증명 `{"api_key":"abc"}`, `"password": "x"`, `'secret':'y'` — 이름이 token/key/secret/password/passwd/pwd로 끝나는 키의 값 가림(이미 있는 이름=값 규칙과 같은 기준).
3. 유닉스 시각(10자리·13자리 숫자, 예 1764120000, 1764120000123)이 전화번호로 오탐되는 문제 — 전화번호 규칙은 한국 휴대폰·일반 번호 모양(구분자·010 등)에 맞추고 순수 10/13자리 시각은 남긴다. 단 오탐을 줄이다 실제 전화번호가 새지 않게 경계 사례를 시험표에.
4. 카드 번호: **아직 결정 안 됨** — 규칙을 넣지 말고 PR 본문 '사용자 결정 필요'에 선택지(넣음: 13~19자리+Luhn 검사 / 안 넣음)와 오탐 예시만.
5. DB advisor 경고 `private.sum_hist` search_path 미설정 → 새 마이그레이션으로 `set search_path=''`(동작 불변, pgTAP로 확인).
