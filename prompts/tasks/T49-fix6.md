# 쉽앤핑 T49-fix6 — 로그인 세션에 구독을 묶어 서버가 최종 보장 (클라이언트 정리 실패와 무관하게)

너는 Orca 작업 에이전트(Codex)다. 기존 브랜치 `feat/T49-pwa-push`(PR #46)에 이어서 커밋. main 합치기 금지. Windows — Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 6차 지적 (높음)
`web/src/data.ts` 192~201행: 소유권 조회나 브라우저 구독 해제가 실패하면 구독·서버 행이 남은 채 468행에서 로그아웃 → 이후 이전 회원의 새 문제가 발송 직전 소유권 검사를 통과해 공유 기기에 표시될 수 있음.

## 매니저 결정 — 서버가 최종 보장
1. 구독 저장 시 **현재 로그인 세션 ID**(Supabase JWT의 `session_id` 클레임, `auth.jwt()->>'session_id'`)를 `push_subscriptions.session_id`로 함께 저장(새 마이그레이션, 기존 파일 수정 금지). 기존 행은 session_id 없음 → 발송 대상에서 제외하고 '다시 켜기 필요'.
2. 발송 대상 조회·발송 직전 재확인 모두 **`auth.sessions`에 그 세션이 아직 있고(로그아웃 시 Supabase가 삭제) 만료되지 않았을 때만** 보낸다. 세션이 없으면 보내지 않고 구독 행 삭제. 토큰 갱신은 같은 session_id를 유지하므로 정상 사용자에게 영향 없음 — 테스트로 확인.
3. 클라이언트 정리는 최선 노력으로 유지하되, 실패해도 signOut 진행(이미 그렇게 됨). 로그아웃 성공 = 세션 삭제 = 서버가 더 이상 안 보냄.
4. 권한: auth.sessions 조회는 security definer 함수 안에서만, service_role 전용. RLS 유지.
5. 회귀 테스트: 정리 실패 + 로그아웃 → 다음 발송 차단·행 삭제, 같은 회원 토큰 갱신 후 계속 수신, 다른 기기 로그아웃이 이 기기 구독에 영향 없음(세션별). 변형 검사.
