# 쉽앤핑 T34 — 연결 요청문에 서버 키 포함 + 안전 장치

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. **머지 금지.** Windows — 웹 테스트·빌드는 로컬, Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 사용자 결정 (2026-11-26, 그대로)
비전공자가 키를 따로 넣는 법을 모를 수 있어서 "그냥 요청문에 한번에 하는게 좋지 않아?" → 선택지 중 **"키 포함 + 안전 장치"**.
이로써 기능명세서 6.0의 "서버 키는 요청문에 넣지 않는다"를 **연결 요청문(S4)에 한해** 바꾼다. **문제 해결 요청문(S7·깊게 보기 등)에는 지금처럼 키를 절대 넣지 않는다.**

## 할 일 (테스트 먼저)
1. **S4 연결 요청문에 키 포함**: 지금 [서버 키 복사]로 따로 주던 키(서버 있음이면 `sp_srv_…`, 브라우저만이면 `sp_pub_…`)를 요청문에 넣는다. 키는 요청문 안 **정해진 한 줄**("이 앱의 쉽앤핑 키: …")에만, 데이터 블록 규칙(6.0)과 충돌하지 않게.
2. **안전 장치 문장**(요청문에 고정 문장으로):
   - "키를 코드·커밋·로그에 직접 쓰지 마. 환경 변수 `SHIP_AND_PING_KEY`(브라우저만이면 빌드 환경 변수)에서 읽게 만들어."
   - "로컬은 `.env`(또는 해당 프레임워크 방식)에 넣고, `.env`가 `.gitignore`에 들어 있는지 확인해. 없으면 추가해."
   - "배포 환경(Vercel·Netlify·Render·Railway·Cloudflare·직접 서버 등)에 이 키를 넣어야 해. 네가 직접 넣을 수 있는 도구가 있으면 넣고, 아니면 내 배포 환경에 맞춰 넣는 방법을 쉬운 말로 3~4단계로 알려 줘."
   - "작업이 끝나면 키가 코드나 커밋에 남지 않았는지 검색해서 확인해."
   - 브라우저만(공개 키) 경우: 공개 키는 브라우저에 보여도 되는 쓰기 전용 키라는 설명과, 그래도 레포에 직접 적지 말고 빌드 환경 변수로 넣으라는 문장.
3. **화면**: 복사 단추 문구 "연결 요청문 복사(키 포함)", 단추 아래 경고 "이 요청문에는 앱의 키가 들어 있어요. 내 코딩 AI에만 붙여 넣고 다른 사람에게 보내지 마세요. 새어 나갔다면 앱 설정에서 [폐기] 후 [재발급]하세요." 따로 키만 복사하는 단추는 보조로 유지. 키를 다시 보여 줄 수 없는 상태(재방문 등)면 요청문을 만들기 전에 "키를 다시 받아야 해요 [재발급]" 흐름 — 기존 키 규칙(재발급 시 이전 키 24시간 유지)을 그대로 따른다.
4. **테스트 갱신**: C14·prompt-safety 테스트에서 "연결 요청문에 키 없음" 단언을 "연결 요청문에는 해당 앱의 현재 키 1개만, 정해진 줄에만"으로 바꾸고, **S7 등 다른 요청문에는 키가 없다**는 단언은 유지·강화. 다른 앱 키가 섞이지 않는지, 재복사 시 전문 일치.
5. 문서: 기능명세서 6.0·S4(버전 올리고 사용자 결정 인용, 바뀐 범위 명시), UX 문서, README 고른 메뉴 표에 이 결정 한 줄, `examples/*/connect.txt`·T10 시나리오가 요청문 형식에 의존하면 맞춘다. `prompts/tasks/T34.md`, 위임 로그 T34 행.
