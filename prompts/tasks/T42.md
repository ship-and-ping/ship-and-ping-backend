## 지금 화면에서 보이는 문제 (운영 캡처 기준)
- 세로 눈금이 0과 최대값(예: 51건)뿐, **점선 가이드 줄 없음** → 막대 높이를 읽을 수 없다.
- "걸린 시간" 제목 아래 "최근 1시간에 걸린 시간 기록이 없어요."가 뜨는데 그 아래 그래프에는 점이 있다 → 모순처럼 읽힌다.
- 단일 시리즈인데 범례 상자가 있다(제목이 이름을 대신해야 함). 섹션 제목 색이 본문보다 흐리다.
- 막대 기간(1시간?)과 툴팁 기간이 화면에 안 쓰여 있다. 실패(빗금 빨강) 막대가 실제 데이터에서 잘 보이는지 트루바 "기타" 기능(오늘 14:15~14:20 실패 30건)으로 확인.
- 대시보드 전체(앱 홈 → 기능 목록 → 기능 상세 → 문제)에서 "지금 상태 → 이유 → 할 일"의 순서가 화면마다 다르다(확인 후 판단).

## 차트 원칙 (dataviz 요약 — 위반하면 안 됨)
1. 형태 먼저, 색은 마지막. 한 숫자가 답이면 차트 대신 큰 숫자 카드.
2. **축 하나**: 건수와 초를 한 그래프에 두지 않는다(지금처럼 분리 유지).
3. 가이드 줄: **옅은 점선 가로 줄 3~5개**(깔끔한 값 0·10·20·30·40·50 같은 nice tick), 축·격자는 뒤로 물러나게(muted 색, 1px). 세로 점선은 시각 눈금에만 아주 옅게 또는 생략.
4. 막대: 얇게, 위쪽 끝만 4px 둥글게, 바닥에 붙임, 막대 사이 2px 여백, 쌓기(성공 아래·실패 위)일 때 조각 사이 2px 표면색 간격. 선: 2px, 점 8px 이상, 겹치는 점은 2px 표면색 테두리.
5. **숫자 라벨은 선택적으로만**(최대값·마지막 값 정도). 모든 점에 숫자 금지.
6. 단일 시리즈는 범례 상자 없이 제목이 이름. 2개 이상이면 범례 + 색만으로 구분하지 않기(실패 빗금 유지).
7. 글자는 텍스트 색 토큰만(시리즈 색으로 글자 쓰지 않기). 상태색(정상/주의/문제)은 상태에만 쓰고 아이콘+글자와 함께.
8. 툴팁 기본: 막대는 막대별, 선은 세로 십자선+툴팁. 조작 영역은 표시보다 크게. 기간 필터는 그래프 위 한 줄.
9. 표로 보기 유지. 다크 모드는 별도 단계 색으로(자동 반전 금지) — 밝은·어두운 대비 4.5:1(글자)·3:1(표시) 계산해서 확인.
10. 마지막에 실제로 렌더링해 캡처를 눈으로 보고 라벨 겹침·넘침 확인.

## T42 추가: 휴대폰 전용 배치 방향

사용자 결정(2026-11-27): 쉽앤핑은 별도 네이티브 앱 없이 같은 웹 주소를 휴대폰에서 '앱처럼' 쓴다. 휴대폰 사용 핵심 흐름 = 알림(앱 푸시·메일) 누름 → 문제 화면 → 지금 괜찮은지 확인 → AI 요청문 복사. 앞으로 알림 기본은 홈 화면 앱(PWA) 푸시, 메일은 대비용, 슬랙은 팀용 선택 항목. 시안 3개 각각에 390px '휴대폰 전용 배치'(PC 축소판이 아니라 첫 화면 상태 요약, 문제 화면 맨 위 큰 요청문 복사 버튼, 그래프는 접기, 엄지 닿는 아래쪽 주요 버튼)를 넣고, 알림 설정 화면을 '앱 푸시(홈 화면에 추가 안내 포함) / 메일 / 슬랙(선택)' 순서로 바꾼 전/후도 한 장 추가해 줘. 구현(PWA·푸시)은 이번 단계에서 하지 않는다.

## T42 레퍼런스 확정: 토스+PostHog+Plausible, 비슷하게라도 높은 완성도

사용자 결정(2026-11-27): 레퍼런스 = 토스(큰 숫자+짧은 문장, 한 화면 한 메시지, 넉넉한 여백, 부드러운 카드, 친절한 문구) + PostHog(캐릭터로 딱딱함 풀기 — 쉽앤핑 양을 빈 화면·로딩·정상/축하 순간에, 정보는 또렷하게) + Plausible(https://plausible.io/plausible.io 데모: 위 핵심 숫자 카드 3~4개 → 가운데 점선 눈금 그래프 하나 → 아래 목록, 한 페이지 구조). 색은 쉽앤핑 토큰 그대로.

사용자 피드백: '맨날 이렇게 보면 뭔가 다르고 아쉬운데 이번엔 비슷하게서라도 퀄리티 높게'. 그래서 이번에는:
1) 시작 전에 세 사이트를 실제로 열어 1440px·390px 캡처를 docs/design/dashboard-2026-11-27/refs/에 저장(Plausible는 데모 대시보드, 토스는 toss.im과 공개된 앱 화면 이미지, PostHog는 홈·제품 페이지).
2) 레퍼런스의 간격·글자 크기 단계·카드 모서리·그림자·그래프 굵기·점선 눈금을 실제 값으로 측정해 표로 적고, 시안에 그 수준으로 맞춘다(쉽앤핑 토큰으로 치환). 로고·문구·이미지·고유 일러스트는 복사 금지.
3) 시안마다 '레퍼런스 캡처 | 우리 시안'을 나란히 둔 비교 이미지를 만들고, 스스로 차이를 점검해 완성도가 레퍼런스보다 떨어지는 곳을 고친 뒤에 제출. 대충 비슷한 와이어프레임 수준 금지 — 실제 서비스 화면처럼 실데이터 예시, 빈/로딩/문제 상태까지.
4) 3안은 같은 레퍼런스 조합 안에서 강조점만 다르게(A Plausible 구조 중심, B 토스식 상태 요약 중심, C PostHog식 캐릭터·친근함 중심). 앞서 보낸 휴대폰 전용 배치와 알림 설정 전/후 요청은 그대로.
