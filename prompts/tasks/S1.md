# 쉽앤핑 S1 — 웹·DB 정제 규칙을 공통 시험표와 일치시키기

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. 머지 금지.
같은 시간에 Windows 작업자가 `worker/`(T4)를 고치고 있다 — `worker/`는 건드리지 않는다.

## 배경
명세 6.0은 개인정보·키 가림을 '같은 규칙으로 두 번'(수집 때 Worker, 표시·복사 때 웹, 저장 때 DB) 적용하라고 한다. 공통 시험표 `docs/specs/sanitize-vectors.json`(mask 30 + route 9)으로 Rust Worker는 39개 모두 통과하지만, 검증 결과 **웹 displayText는 mask 26/30, DB private.mask는 23/30, DB private.route는 route 2/9**만 같다.
- 웹이 다른 사례: Basic 인증 2개, Cookie·줄 구분자 1개(웹은 줄 구분자를 공백으로 바꾸고 Cookie 규칙이 없음), `Bearer: demo; token=test`.
- DB mask는 위 넷 + 전각·0폭·방향 문자 3개(정규화 없음).
- DB route는 T3의 옛 로직.

## 할 일 (테스트 먼저)
1. **웹**: `web/src`의 정규화·가림(displayText 등)을 Rust `worker/src/ingest.rs`의 규칙과 같게 고치고, `docs/specs/sanitize-vectors.json`을 읽어 30+9 사례를 모두 검사하는 Vitest 테스트 추가(시험표를 import). 단, 화면 표시에서 줄바꿈을 공백으로 바꿔야 하는 곳은 '가림 결과'와 '표시 형식'을 분리해서 가림은 시험표와 같게.
2. **DB**: 새 마이그레이션으로 `private.mask`·`private.route`를 같은 규칙으로(정규화: NFKC는 PG `normalize(..., NFKC)`, 0폭·방향 문자 제거, U+2028/2029/0085 → 줄바꿈). pgTAP에서 시험표 사례를 검사(시험표 JSON을 테스트 실행 중 읽기 어렵다면 같은 사례를 SQL로 옮기고, 사례 수·id가 시험표와 같은지 검사하는 스크립트 테스트를 web 쪽에 추가). 기존 마이그레이션 수정 금지, 권한·search_path 유지.
3. **긴 앱 이름**: 공백 없는 40자 앱 이름이 390px S2 카드 h2·머리말에서 넘치지 않게(그 요소에만 overflow-wrap: anywhere 또는 break-word). 테스트 또는 캡처.
4. 시험표 자체를 고쳐야 한다고 판단되면 고치지 말고 PR 본문에 근거와 제안(Worker와 함께 바꿔야 하므로).
5. 이 지시문을 `prompts/tasks/S1.md`로, 위임 로그 6칸은 PR 본문에.

## 지킬 것
명령은 경로를 그대로 써서 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 편집 도구로. 테스트의 키 모양 문자열은 실행 중 조립(리터럴 금지).
