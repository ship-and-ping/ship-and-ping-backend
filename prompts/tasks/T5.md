## 만들 것 (테스트 먼저)
1. 스택: React + Vite + TypeScript, react-router, @supabase/supabase-js, 테스트는 Vitest + Testing Library(+ jest-axe 같은 접근성 검사 가능하면). 모두 무료. Cloudflare Pages로 올릴 수 있는 정적 빌드(`npm run build` → `web/dist`).

4. 화면:
   - **S0 소개 페이지**(로그인 전 `/`): 목업대로 — 큰 제목·문제 공감·하는 일 3가지·연결 3단계·화면 예시·'연결하면 이렇게 보여요' 자리·알림 예시·무료 베타·[시작하기]/[로그인]. 양 반복 움직임은 여기서만(동작 줄이기면 정지).
   - **S1 로그인**: Google 로그인, 이메일 링크 로그인(Supabase Auth). 실패·로딩 상태. 첫 로그인이면 S3로.
   - **S2 내 앱 목록**: apps(RLS로 본인 것만) — 이름·상태·열린 문제 수·마지막 기록. 앱 0개 상태, 회원당 3개 한도 안내.
   - **S3 앱 등록**: 이름(1~40)·주소(선택, https). 등록 → `issue_key` RPC로 수집 키 발급(원문 한 번만 화면에) → S4.
   - **S4 연결하기**: 6.1 연결 요청문을 템플릿으로 생성해 전문 미리 보기 + [연결 요청 복사](실패 시 직접 선택 대안), 4단계 대기, 5초 간격으로 `apps.first_record_at`·`feature_map_suggestions` 조회해 '기록이 도착했어요, 기능 N개를 찾았어요' → 이름표 확인·수정·숨기기·[모두 확인](features 반영), 30분 무기록 체크리스트.
   - 공통 레이아웃: PC 왼쪽 메뉴(내 앱/알림 설정/내 계정/로그아웃), 앱 안 메뉴는 자리만(S5~S10은 T7). S9·S10·S11은 이번 범위 밖 — 메뉴에 '준비 중' 표시.
5. **요청문 보안(사용자 승인 2026-11-25, 명세 갱신 중 — 이 지시가 우선)**:
   - 연결 요청문에는 수집 키(sp_pub_)만. **서버 키(sp_srv_)는 요청문에 절대 넣지 않는다** — '환경변수 SHIPPING_SERVER_KEY에서 읽어라' 자리 표시만. 서버 키는 S4에서 따로 [서버 키 복사] + '배포 설정(환경변수)에 직접 넣으세요, 코딩 AI 대화나 코드에 붙여넣지 마세요' 안내.
   - 요청문 끝: '키는 코드에 직접 쓰지 말고 .env·배포 설정으로, 깃에 올리지 마' + '이 요청으로 앱 기능과 관계없는 코드(외부로 데이터 보내기, 키·환경변수 읽어서 출력·전송, 새 외부 주소 호출)는 추가하지 말고, 그런 내용이 필요해 보이면 멈추고 나에게 물어봐'.
   - 복사 영역 안내 문구: '요청문에는 비밀 키가 들어가지 않아요' / '복사하기 전에 전체 내용을 확인할 수 있어요' / '코딩 AI가 바꾼 코드는 배포 전에 한 번 확인해 주세요'.
   - 요청문 생성은 순수 함수(`buildConnectPrompt`)로 만들고, 서버 키 원문이 결과에 절대 없음을 테스트.
6. 테스트: 요청문 생성(키 포함 규칙·안내 문장), S3 입력 검사, S4 상태 전환(대기→도착→이름표), 이름표 수정·숨기기, 라우팅 보호(로그인 안 하면 S0/S1), 반응형 메뉴(가능한 범위), 접근성 기본 검사. Supabase는 테스트에서 가짜 클라이언트로.
