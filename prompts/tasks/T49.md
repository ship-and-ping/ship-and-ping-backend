명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 사용자 결정 (2026-11-27)
알림 기본 = 홈 화면 앱 푸시, 메일 = 대비용, 슬랙 = 팀용 선택. "b로 해줘(PWA+푸시). 하면 내가 아이폰으로 설치할게". 비용 0원, 새 유료 서비스 금지.

## 1. 홈 화면 앱 (web)
- `manifest.webmanifest`(이름 쉽앤핑, short_name, start_url `/apps`, display standalone, 토큰 색 theme/background, 양 아이콘 192·512·maskable), `apple-touch-icon`, iOS 메타(apple-mobile-web-app-capable·status-bar-style·title). 아이콘은 `docs/design/brand/` 양 이미지로 생성해 커밋.
- 서비스 워커 `sw.js`(루트 범위): **push 수신 → 알림 표시**, **notificationclick → 알림의 문제 화면 URL 열기/포커스**. 페이지 캐시는 하지 않거나 정적 자산만(로그인·API·배포 갱신을 깨지 않게). `web/pages-headers.ts`: sw.js `Cache-Control: no-cache`, 올바른 content-type, CSP가 워커 등록을 허용.
- 설치 안내: 알림 설정 화면 '앱 푸시' 칸에 기기별 안내 — 아이폰: "Safari 공유 버튼 → 홈 화면에 추가 → 홈 화면의 쉽앤핑으로 열기 → 푸시 켜기"(iOS 16.4+ 필요, 홈 화면 앱에서만 가능함을 안내), 안드로이드/PC: 설치 버튼(beforeinstallprompt). 이미 홈 화면 앱(standalone)이면 안내 대신 '푸시 켜기'.

## 2. 푸시 구독 (web + DB)
- '푸시 켜기' 버튼(사용자 탭에서만 권한 요청) → `Notification.requestPermission` → `pushManager.subscribe({userVisibleOnly:true, applicationServerKey: VITE_VAPID_PUBLIC_KEY})` → 구독 저장. 끄기·기기 삭제, 권한 거부 시 설정 방법 안내, '시험 푸시 보내기'.
- DB(새 마이그레이션, 기존 파일 수정 금지): `public.push_subscriptions`(user_id, endpoint unique, p256dh, auth, user_agent 요약, created_at, last_ok_at, failures) RLS 본인만, endpoint는 https만·길이 제한. `alert_channels.push_enabled`(기본 true — 구독이 있으면 받음). evaluate_all 알림 행 생성에 'push' 채널 추가(구독이 있고 push_enabled일 때), claim_notifications가 push 대상 구독을 돌려주게(권한 service_role만).
- 메일은 대비용으로 유지: 기존 email_enabled 동작 그대로.

## 3. 푸시 발송 (worker, Rust)
- Web Push 표준: VAPID(ES256 JWT, `aud`=엔드포인트 origin, `exp`≤12h, `sub`=`https://ship-and-ping.pages.dev`) + 페이로드 암호화 RFC 8291 aes128gcm. 순수 Rust 크레이트(p256·ecdsa·hkdf·sha2·aes-gcm 등, wasm 빌드 가능)로, 외부 유료 서비스 없이. RFC 8291 테스트 벡터로 단위 테스트.
- 페이로드: 제목 "[쉽앤핑] 트루바 · 장소 목록 보기가 느려졌어요", 본문 한 줄("평소 약 0.2초 → 지금 약 1.4초"), url(문제 화면). 키·요청문·오류 문구 금지. TTL·urgency high.
- 응답 404/410 → 구독 삭제, 그 외 실패는 재시도 후 기록. 푸시 실패해도 메일은 나가게.
- Worker secret: `VAPID_PRIVATE_KEY`(없으면 푸시만 건너뛰고 나머지 정상 — 기존 '선택 secret' 패턴), 공개키 `VAPID_PUBLIC_KEY`. 웹 빌드 `VITE_VAPID_PUBLIC_KEY`(deploy.yml에 env 추가). **키는 코드·로그에 절대 넣지 않는다.** 키 생성은 레포에 의존성 없는 Node 스크립트 `scripts/generate-vapid.mjs`(WebCrypto P-256, base64url 출력)로 — 사용자가 직접 실행해 값을 Cloudflare/GitHub에 넣는다. `docs/deploy.md`에 넣는 곳 3군데를 비전공자용 순서로.
