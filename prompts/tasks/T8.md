너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. 머지 금지.

## 먼저 읽기
- 기능명세서 3장 S9·S11(알림 요약), 8장(알림), 9장(슬랙 webhook 폐기·메일 한도), 10장 C9, 6.0(알림에 원문·키 넣지 않음)
- `docs/research/2026-11-24-free-tier-constraints.md` 5장(Slack: incoming-webhook OAuth, 채널당 초당 1건, 무료 워크스페이스 앱 10개)·6장(Resend 무료 하루 100건)

## 만들 것 (테스트 먼저)
1. **발송(Worker Cron, 판정 직후)**: `claim_notifications(limit)`로 대기 알림을 선점 → 채널별 발송 → `complete_notification`.
   - 검증 지적 반영: **선점 토큰**을 도입(claim이 토큰 반환, complete는 토큰이 맞을 때만 완료 — 10분 넘는 발송의 이중 완료 방지), `ok=false`는 최대 3번 재시도(지수 대기) 후 실패 종결, 숨긴/닫힌 문제의 대기 알림은 발송하지 않고 종결.
   - 슬랙: incoming webhook 주소(Vault 저장분 복호화는 DB 함수로 service_role만)로 POST. 같은 회차에 같은 채널로 여러 건이면 한 메시지로 합침(초당 1건 한도). 404·410·`channel_not_found`·`invalid_token`이면 webhook 끊김으로 표시하고 그 회원의 이메일로 대체 + S9 경고.
   - 이메일: Resend API(`RESEND_API_KEY` 환경값, 없으면 발송 건너뛰고 '설정 필요' 기록). 쉽앤핑 전체 하루 90건 넘으면 그날 나머지는 다음 날 아침 묶음 메일. 받는 주소는 로그인 이메일.
   - 메시지: 명세 8장 문장(쉬운 한국어) + [쉽앤핑에서 보기] 링크. **오류 원문·주소 원문·키 넣지 않음**(공용 표시 규칙).
   - 발송 오류 메시지는 저장 전 가림(webhook 주소·키 제거).
2. **슬랙 연결(OAuth)**: Worker에 `/v1/slack/install`(state 생성 — 회원 세션 확인, CSRF 방지)·`/v1/slack/callback`(code 교환 → `incoming_webhook.url`·channel 저장, Vault). 환경값 `SLACK_CLIENT_ID`·`SLACK_CLIENT_SECRET`(없으면 '설정 필요' 응답). 무료 워크스페이스 앱 10개 한도·`action_prohibited` 오류를 쉬운 말로.
3. **S9 알림 설정 화면(web)**: [Slack에 추가], 연결 상태(채널 이름), [시험 알림 보내기], 연결 끊김 경고·다시 연결, 이메일 켜기/끄기, 둘 다 꺼짐 띠. design-system·목업대로, 공용 표시 함수만.
4. **DB(새 마이그레이션)**: 선점 토큰·재시도 횟수 열, slack webhook Vault 저장/조회 함수(service_role만), 회원용 알림 설정 조회·수정 RPC(본인만), 시험 알림 큐 RPC(분당 1회 제한).
5. 테스트: 선점 토큰 이중 완료 방지, 재시도·종결, 숨김/닫힘 미발송, 슬랙 합침·끊김→이메일 대체, 메일 일일 한도·묶음, OAuth state 검증·실패, 메시지에 원문·키 없음(C14 관련), S9 화면 상태, pgTAP 권한. 외부 API는 가짜 서버로.
6. 문서: `worker/README.md` 환경값 표(SLACK_CLIENT_ID/SECRET, RESEND_API_KEY, 발신 주소), `db.md` 갱신, 이 지시문을 `prompts/tasks/T8.md`로, 위임 로그 6칸은 PR 본문.
