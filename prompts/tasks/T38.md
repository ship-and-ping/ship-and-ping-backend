# 쉽앤핑 T38 — 기능 지도 이름을 확인 없이 바로 적용

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. **머지 금지.** Windows — 웹 테스트·빌드는 로컬, Rust·DB 테스트는 PR CI로.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.
동시에 T37(디자인 QA 3차)이 `web/`의 문구·배치·스타일을 고친다. 웹은 **이름표 확인 흐름에 필요한 부분만** 최소로 바꾸고, 겹치면 PR 전에 `git merge origin/main`.

## 사용자 결정 (2026-11-26, 그대로)
"ai 요청 사항에 한번 쓰면 다 등록 되게 해야하는거 아니야?" — 연결 요청문으로 코딩 AI가 보낸 기능 지도(`POST /v1/feature-map`)의 이름을 **사용자 확인 없이 바로 기능 이름으로 적용**한다. 기존 규칙(기능명세서: "제안으로만 저장, 회원이 S4·S10에서 확인해야 반영")을 바꾼다.

## 규칙
1. 기능 지도가 오면 같은 앱의 `method + route`가 일치하는 자동 기능에 이름을 바로 적용. 아직 기록이 없는 주소는 제안으로 보관했다가 **그 주소의 기능이 처음 생길 때 자동 적용**.
2. **사용자가 직접 고친 이름(confirmed)은 절대 덮어쓰지 않는다.** 이름 출처를 구분(`route`=없음 / `ai`=기능 지도 자동 / `confirmed`=사용자). 나중에 온 기능 지도는 `route`·`ai`만 갱신.
3. 이름 값은 기존 정제·길이 제한(6.2 기준, 40자, 지시 문장 막기)과 표시 안전 규칙(6.0) 그대로 거친 뒤 적용. 정제에 걸려 비면 "이름 없는 기능" 유지.
4. 화면: S4·S10의 "이름 확인" 단계는 "AI가 붙인 이름이에요. 고칠 것만 고치세요"로 바꾸고 [모두 확인] 필수 단계를 없앤다. 앱 홈·기능 목록은 적용된 이름을 바로 표시.
5. **기존 데이터 반영**: 새 마이그레이션(20261126500000번대)에서 이미 쌓인 제안(`feature_map_suggestions`)을 `name_source='route'`인 기존 자동 기능에 한 번 적용(백필). confirmed는 건드리지 않음.
6. 베타 정원(앱당 20개 등) 규칙은 그대로 — 이름 적용이 자리를 차지하지 않는다.

## 테스트 먼저
기능 지도 수신 즉시 적용, 기록 없는 주소는 첫 생성 때 적용, confirmed 보존, 정제 실패 시 유지, 다른 앱 지도 미적용, 백필(제안 있음/없음/confirmed), 화면 표시.
