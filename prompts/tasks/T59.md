## 바꿀 것
1. **대기 시간(queue_ms)**: 연결 요청문 계측을 "요청을 받은 순간"부터 재게 한다. 우선순위: ① 프록시가 넣는 `X-Request-Start`(nginx `t=${msec}`, Heroku·Render 등) ② 서버 프레임워크가 아는 수신 시각(예: Tomcat `Request#getCoyoteRequest().getStartTime()`, Node `req` 수신 시각) ③ 둘 다 없으면 생략(추측 금지). 기록은 `duration_ms`(받은 순간~응답 끝) + `queue_ms`(받은 순간~핸들러 시작). 시계 차이로 음수·비정상 값은 버린다. 요청문은 스택별 짧은 예시만, 비밀값·개인정보 안 보냄.
2. **멈춤·끊김**: 응답을 끝내지 못한 요청(클라이언트 끊김, 서버 타임아웃, 예외 없이 끊긴 연결)을 `failure`(종류 `aborted`/`timeout`)로 기록하게 한다. 서버가 나중에 응답했더라도 `duration_ms`가 설정 타임아웃(모르면 10초)을 넘으면 실패로 센다.
3. **판정 반영**: 느림 판정과 화면의 걸린 시간은 대기 포함 시간 기준. 화면·AI 요청문에 "처리 전 대기 0.4초(전체의 70%)"처럼 비중을 보여 주고, 대기 비중이 크면 요청문이 **코드보다 서버 자원(CPU·스레드 풀·인스턴스 크기)**을 먼저 의심하게(T54 서버 기록·T55 유형과 연결). 기존 앱(대기 값 없음)은 지금처럼 동작.
4. **짧은 멈춤 감지**: 1분 안에 요청 흐름이 갑자기 0이 되고 끊김·타임아웃이 몰리는 경우를 문제로 연다(T54의 10분 '기록 없음'과 구분). 잘못 울림 방지: 평소 요청이 분당 N건 이상인 기능만, 기준과 근거 문서화.
5. Trova 4차 수치로 만든 예시 데이터로 "이전 방식이면 경보 없음 → 새 방식이면 경보 + 요청문이 CPU/대기 지목"을 테스트로 고정.
