# 쉽앤핑 T26 — 웹 후속: 비밀번호 변경 재인증 + T21·T22 낮은 지적

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. **머지 금지.**
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 동시에 도는 작업 — 파일 겹치지 않기
T24(PR #23)가 `web/src/normalize.ts`·`web/src/display*`·정제 테스트·`worker/src`·`supabase/`, T25(PR #21)가 `web/vite.config.ts`·`docs/deploy.md`·`.github/workflows/`·`worker/wrangler.toml`을 고친다. **그 파일들은 건드리지 않는다.** 네 범위: `web/src/data.ts`·`AuthPage.tsx`·`Account.tsx`·`App.tsx`와 그 테스트, `docs/monitoring-service-ux.md`(해당 상태만), `prompts/tasks/T26.md`, 위임 로그의 T26 행.

## 먼저 읽기
`prompts/tasks/T21.md`·`T22.md`, 기능명세서 S1·S11, UX 문서 S11·4장 상태 표, Supabase JS `reauthenticate()`와 `updateUser({ password, nonce })` 동작.

## 만들 것 (테스트 먼저)
1. **비밀번호 변경 재인증**: 운영에서 "Secure password change"(최근 24시간 안에 로그인하지 않았으면 재인증 필요)를 켤 수 있게 — S11 비밀번호 바꾸기/만들기에서 재인증이 필요하다는 오류가 오면 `reauthenticate()`로 메일 인증번호를 보내고, 번호 입력 칸을 보여 준 뒤 `updateUser({ password, nonce })`. 안내 문구 쉬운 한국어("본인 확인을 위해 메일로 보낸 번호를 적어 주세요"), 재전송·만료·틀린 번호 상태. 비밀번호는 비제어 입력 유지(상태·저장소에 남기지 않기).
   - 이 경우 Supabase의 'Reauthentication' 메일이 간다. 메일 양식(`supabase/templates/reauthentication.html`)을 기존 세 양식과 같은 디자인으로 만든다(`{{ .Token }}` 표시, 버튼 없음). — `supabase/templates/`는 T24 범위가 아니므로 이 파일만 추가 가능.
2. T21 낮음(웹): 탈퇴 재시도 429를 '확인 중'(2분 대기)으로 받지 말고 "잠시 뒤 다시 시도해 주세요"로(`data.ts:110` 부근), 만료 토큰 401은 `refreshSession`으로 확인한 뒤에만 "탈퇴가 이미 끝났을 수 있어요"(`data.ts:104-108`).
3. T22 낮음: `Account.tsx:64` 재조회 실패 때 저장 완료 안내·포커스 유지, `AuthPage.tsx:97` 재설정의 same_password·weak_password 오류를 "새 링크 받기"가 아니라 칸 아래 입력 오류로.
4. 이 지시문을 `prompts/tasks/T26.md`로, 위임 로그 T26 행(6칸), PR 본문에 '운영에서 바꿀 설정'(Secure password change 켜기, Reauthentication 메일 양식).

## 지킬 것
실제 외부 서비스 호출 금지, 키 모양 리터럴 금지, 화면 출력은 공용 표시 함수만, 계정 존재 비노출 원칙 유지.
