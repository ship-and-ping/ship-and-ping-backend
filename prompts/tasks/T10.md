# 쉽앤핑 T10 — 예제 웹앱 2개로 완료 조건 C1~C14 전체 확인 (밤샘 작업)

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. **머지 금지.** 사용자는 자는 중이라 질문할 수 없다 — 막히면 가정을 적고 안전한 쪽으로 진행, 사람이 해야 하는 것은 PR 본문 '사람이 해야 할 일'에 모은다.
명령은 경로를 그대로 하나씩 쓴다. 셸 변수·명령 치환·인터프리터 한 줄 실행(`python -c`, `node -e`) 대신 경로를 그대로 쓰고 파일은 Read·Write(편집) 도구로 다룬다.
이 기기(Mac)에는 Docker와 `~/.cargo/bin/cargo`가 있다. 새 도구 전역 설치 금지(npx 고정 버전·프로젝트 devDependency는 가능).

## 동시에 도는 다른 작업 — 파일 겹치지 않기
다른 작업자(T20)가 **`web/` 전체와 `docs/design/qa/`**를 고치고 있다. 너는 `web/` 아래 파일을 **수정하지 않는다**(읽기·실행만). 웹 쪽 문제를 찾으면 고치지 말고 PR 본문 '웹 쪽 발견'에 적는다.
네 범위: `examples/`, `scripts/`, `supabase/tests/`, `worker/`의 테스트(코드 버그를 찾으면 최소 수정 + 테스트), `docs/verification/`, `prompts/tasks/T10.md`, `.github/workflows/`(새 검사 추가 시).

## 먼저 읽기
- 기능명세서 10장 완료 조건 C1~C12와 6.0의 C14 사례(①~⑳), 4장(수집 형식)·5장·7장(판정)·8장(알림)
- `db.md`, `supabase/migrations/`, `supabase/tests/`, `worker/src/`, `web/src/`(Connect 연결 요청문·issue-prompt — 읽기만), `docs/specs/sanitize-vectors.json`, `examples/README.md`, `scripts/check-deliverables.sh`, `.github/workflows/`

## 만들 것
1. **예제 웹앱 2개 (`examples/`)**
   - `examples/with-server/`: 작은 서버가 있는 웹앱(예: Node 표준 라이브러리 http 서버 + 정적 페이지, 의존성 최소). 신청·조회 같은 기능 2~3개.
   - `examples/browser-only/`: 서버 없이 브라우저만 쓰는 정적 웹앱.
   - 각 앱에 **웹이 실제로 만드는 연결 요청문**(Connect 화면 로직이 만드는 문장 그대로 — 테스트나 스크립트로 생성해 저장)을 너 자신이 코딩 AI 역할로 적용한다. 적용 전 원본과 적용 후 코드를 둘 다 남겨(`before/`·`after/` 또는 커밋 분리) "요청문만으로 연결됐는지" 보이게.
2. **로컬 전체 흐름 확인** — 실제 Supabase·Cloudflare·Slack·Resend에는 연결하지 않는다.
   - 로컬 Supabase(`npx --yes supabase@2.75.0 start` / `db start`) + 로컬 Worker(wrangler dev 등, 프로젝트에 이미 있는 방법 우선) + 예제 앱을 띄워 기록 전송 → 첫 기록 도착 → 기능 이름표 제안까지(C2).
   - 시나리오 데이터 스크립트(`scripts/`)로 실패 20%, 느려짐 2배, 결과 미확인 급증, 새 버전 5건 연속 성공, 사용 없음, 평소 속도 전/후(30건·3일 — 시간은 DB에 과거 시각을 넣어 재현)를 만들어 `evaluate_all`을 돌리고 문제 열림·알림 1번·해결됨을 확인(C6·C7·C8).
   - 알림 전송은 가짜 수신 서버(로컬 http)로 받아 횟수·내용 확인, webhook 폐기(404/410) 시 이메일 대체 경로 확인(C9 — 실제 Slack은 '사람이 해야 할 일').
3. **조건별 자동 검사** — 가능한 것은 다시 돌릴 수 있는 테스트로(pgTAP `supabase/tests/`, `cargo test`, 스크립트):
   - C1 두 회원 A·B의 서로 앱·기록·문제 읽기 거부(화면 API 경로 + Supabase 직접 조회)
   - C3 수집 키로 `source=server`, 다른 앱 지정, 조회 시도 거부
   - C4·C14 금지 항목·주입 문구가 DB·AI 요청문 어디에도 원문으로 남지 않음(공통 시험표 그대로)
   - C5 64KB·100건 묶음 처리 — 로컬에서 처리 시간 측정값만 기록하고 '실측은 Cloudflare 대시보드 필요'로 표시
   - C10 30일 지난 요약·시도·오류 예시 정리, 시간별·하루 요약은 남음(현재 보관 규칙: 5분 7일 → 시간별 30일 → 하루 1년)
   - C11 비밀값 검사 통과, C12 `scripts/check-deliverables.sh` 결과(T11에서 채울 빈칸은 목록만)
   - 이미 있는 테스트가 조건을 덮으면 새로 만들지 말고 어느 테스트인지 연결만.
4. **결과 문서** `docs/verification/2026-11-26-T10.md`: 조건마다 "확인 방법 · 결과(통과/실패/사람 필요) · 근거(테스트 이름·명령·출력 요약·캡처 경로)". 실패는 원인과 고친 것/못 고친 것. 사람이 해야 하는 것(Cloudflare CPU 실측, 실제 Slack, 실제 메일, 실제 코딩 AI로 적용)은 따로 표.
5. 한 번에 다시 돌리는 명령: `scripts/verify-local.sh`(또는 npm 스크립트) — 로컬 스택 띄우기 → 시나리오 → 검사 → 정리.
6. 이 지시문을 `prompts/tasks/T10.md`로 복사, 위임 로그 6칸(목표·프롬프트·결과·검증·수정·배운점 한줄)은 PR 본문.

## 지킬 것
- 실제 외부 서비스(운영 Supabase `tzkngvpsygkiegvcagsj`, Cloudflare, Slack, Resend, Google) 연결·호출 금지. 로컬·가짜만.
- 키 모양 리터럴 금지 — 테스트 값은 명백한 가짜(`sp_pub_test_...`처럼 공통 시험표 규칙을 따르되 비밀값 검사에 걸리지 않게). `.env` 파일 커밋 금지.
- 끝나면 로컬 Supabase·Worker·예제 서버를 멈춘다(`supabase stop` 등). Docker 이미지·볼륨 전체 삭제 같은 파괴적 정리는 하지 않는다.
- 화면 출력 규칙(공용 표시 함수, `dangerouslySetInnerHTML` 금지)과 요청문 안전 규칙(6.0)은 예제 앱에도 적용.
- DB 마이그레이션을 새로 만들어야 하면 번호는 20261126000000번대, 이유를 PR에. 기존 마이그레이션 수정 금지.

## 고칠 것 (Claude reviewflow 검수, 심각도 순)
1. **높음 — `worker/src/ingest.rs:483` 부근**: 새로 넣은 app_version 가림이 전화번호(PHONE) 규칙에 걸려 `2026.11.26.1530`, `1764120000`, `v20261126-1530` 같은 빌드 시각형 버전이 `[가림]`으로 합쳐진다 → 새 버전 감지와 C7 해결 판정이 깨진다. 버전에는 **키 형식(공통 시험표의 키 접두사 규칙)만** 가리고 전화번호·숫자 규칙은 적용하지 않는다. 위 세 버전이 그대로 보존되고, 키가 섞인 버전은 가려지는 Rust 테스트 먼저. 공통 시험표(`docs/specs/sanitize-vectors.json`)에 버전 사례를 추가할 필요가 있으면 web·DB 쪽 일치 테스트가 깨지지 않는 범위에서만(웹 코드는 수정 금지 — 필요하면 PR 본문에 제안).
2. **중간 — `scripts/t10-scenario.mjs:317`**: C6 단언이 총 2통만 본다. 회원별로 정확히 1통인지 단언하고, 결과 문서 문장과 일치시킨다.
3. 낮음:
   - `scripts/t10-scenario.mjs:270` C3 수집 키 조회 단언이 항상 통과 — 실제 거부(상태 코드·빈 결과)를 단언.
   - safeupdate 대응 마이그레이션 `20261126000000`에 대한 pgTAP 회귀 테스트(조건 없는 UPDATE가 아닌 설정 행 지정으로 동작) 추가.
