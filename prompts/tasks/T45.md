# 쉽앤핑 T45 — 걸린 시간 숫자 정확도 개선 (구간 끝값 → 실제에 가까운 값)

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 PR까지. **머지 금지.** Windows — 웹은 로컬, Rust·DB 테스트는 PR CI로.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 문제 (2026-11-27 운영 실측)
트루바 느림 시험: 실제 평균 6.35초·대부분 6.0~6.5초인데 쉽앤핑은 p50을 **7.5초**로 기록(`incidents.metric_at_open.p50=7500`). 3초 시험 때도 실제 3.3초가 **5.0초**. `stats_5m.hist` 구간(예: 5~10초)의 끝값/중간값을 그대로 쓰는 것으로 보인다. 화면·알림 메일·요청문에 "보통 7.5초"처럼 실제와 1초 이상 다른 숫자가 나간다.

## 할 일
1. 원인 확인: hist 구간 경계, p50/p95 계산 위치(마이그레이션 SQL `private.evaluation_signals`·baseline·기능 화면 API·notify 문구)를 모두 찾는다.
2. 개선(비용 0, 저장량 크게 늘리지 않게) — 후보를 비교해 고른다:
   a) 구간 안 **선형 보간**으로 분위수 추정, b) 구간을 더 촘촘히(예: 로그 스케일 1.25배 간격), c) duration_sum_ms/total 평균을 함께 표시. 목표: 위 두 실측 사례에서 오차 ±10% 이내. 판정 임계(5초 기본, baseline 비교)가 바뀌어 알림이 과하게/덜 뜨지 않는지 기존 테스트와 새 테스트로 고정.
3. 표시: 화면·메일·요청문의 "보통 n초"가 새 계산을 쓰게. 정확도 한계가 남으면 "약 6.4초"처럼 '약'.
4. 기존 데이터와 호환: hist 형식을 바꾸면 옛 행도 읽히게(마이그레이션은 새 타임스탬프 파일, 기존 파일 수정 금지, 권한 그대로). evaluate_all 동작은 바꾸지 않되 p50 값만 정확해지게.

## 테스트 먼저
실측 재현 케이스(6.0~6.5초 30건 → 약 6.3초, 3.0~3.6초 → 약 3.3초), 경계값, 빈 구간, 옛 hist 형식. 변형 검사.
