## 만들 것 (테스트 먼저)
1. **S8 깊게 볼 기능 추가(web)**: 이름·시작('신청 버튼을 누를 때')·성공 기준('참가자 명단에 저장됐을 때') 입력 → 앱당 최대 5개(DB 트리거 이미 있음 — 화면 안내), [추가 연결 요청 복사](6.2 + 6.0 전부, 빈 칸이면 '(입력 필요)'와 복사 막기, 보이는 폼 값만), 첫 결과 대기 → '첫 신청 기록이 도착했어요. 참가자 명단에 저장되기까지 1.2초 걸렸어요'.
2. **S5·S6·S7에 깊게 보기 표시**: 기능 카드에 성공·실패·중단·결과 미확인을 따로(실패율에는 성공+실패만), 결과 미확인 급증 문제('기록 전송이 끊겼을 수 있어요'), 연속 실패 3건 문제. 실패한 단계(step) 이름은 [자세히]와 AI 요청문에만.
3. **DB(새 마이그레이션)**: 깊게 보기 기능 추가·수정·삭제 RPC(본인 앱만, 이름·정의 정제·길이 제한, feature_key 생성 — 추측하기 어려운 값), 늦게 온 결과가 미확인 → 성공/실패로 바뀌는 처리(이미 있으면 테스트만), attempts 30일 정리 확인.
4. **Worker**: attempt_start/attempt_result 처리와 source=server 규칙이 명세대로인지 확인하고 빈 곳만 보강(정제는 공통 시험표 그대로).
5. 테스트: 입력 검증·5개 한도 안내, 요청문(6.2·C14 해당 사례·서버 키 없음), 첫 결과 도착 전환, 4가지 상태 집계·실패율 분모, 미확인 10분 경계·늦은 결과, 연속 실패 3건, 남의 앱 RPC 거부.
6. 이 지시문을 `prompts/tasks/T9.md`로, 위임 로그 6칸은 PR 본문, 가능하면 S8·S5 캡처.
