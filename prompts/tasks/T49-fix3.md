# 쉽앤핑 T49-fix3 — 공유 기기 처리를 단순하게 바꿔 경합 자체를 없애기

너는 Orca 작업 에이전트(Codex)다. 기존 브랜치 `feat/T49-pwa-push`(PR #46)에 이어서 커밋. origin/main 병합 허용, main 합치기 금지. Windows — Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 배경
3차 보안 검수 미통과: 서비스 워커가 소유권 확인 전 포커스된 창에 이전 회원 UUID를 보냄(`web/public/sw.js:29`), A 확인과 B 세션 활성화 사이 잠금 대기로 A의 앱 이름이 잠깐 보일 수 있는 경합(`web/src/data.ts:348·352·359`, `sw.js:49·55`). 구독 '이전'·소유권 확인 설계가 경합을 계속 만든다.

## 매니저 결정 — 설계를 단순화한다
1. **구독 이전(transfer) 기능을 없앤다.** 로그아웃·계정 전환·탈퇴 시 브라우저에서 `pushManager.getSubscription()?.unsubscribe()` + 서버 행 삭제(실패해도 signOut은 진행, 서버는 다음 발송 때 410/소유자 불일치로 정리). 열린 쉽앤핑 알림은 `getNotifications()`로 닫기.
2. 로그인 후에는 이 기기에 구독이 없으면 알림 설정에 '푸시 켜기'를 다시 보여 준다(한 번 탭). 같은 회원이 다시 로그인해도 다시 켜기 — 단순함을 우선.
3. 서비스 워커는 **창에 회원 ID·앱 정보를 보내지 않는다.** push 이벤트에서 받은 페이로드를 그대로 표시만 하고, 클릭 시 우리 출처의 문제 URL만 연다. 소유권 확인·잠금 대기 코드 제거.
4. 서버: 발송 시 구독의 user_id가 알림 대상 앱 주인과 같은지 확인(다르면 발송 안 하고 삭제) — 이것이 최종 보장.
5. 관련 RPC·마이그레이션 정리(새 마이그레이션으로, 앞 파일 수정 금지), 테스트를 새 설계 기준으로 갱신(로그아웃 시 unsubscribe 호출, 재로그인 시 다시 켜기 표시, 주인 불일치 발송 차단, SW가 postMessage로 식별자를 보내지 않음). 변형 검사.
