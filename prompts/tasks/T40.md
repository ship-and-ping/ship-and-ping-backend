# 쉽앤핑 T40 — 알림 메일을 알아보기 쉽게 (앱 이름 제목 + 양 디자인 HTML + 버튼)

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. **머지 금지.** Windows — Rust 빌드·테스트(cargo)는 이 기기에서 막히므로 **PR 자동 검사(CI)로 확인**한다.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 배경 (2026-11-27 실제 운영 시험)
트루바 실패 시험에서 알림 메일이 정상 발송됐지만 글자만 있는 메일이었다:
- 제목 `[쉽앤핑] 앱 알림이에요` — 어느 앱인지 모름
- 본문 `기타 최근 30분 9건 중 9건이 실패했어요.` + 긴 주소 그대로 — 앱 이름 없음, 주소가 4줄로 쪼개짐, 다음 행동 없음
사용자: "응 맡겨줘" (개선안 승인).

## 먼저 읽기
`worker/src/notify.rs` 전체(특히 `sentence`, `email`, 다이제스트), 알림을 꺼내는 RPC(`supabase/migrations/`에서 notifications claim/deliver 관련 함수 — 앱 이름을 이미 돌려주는지 확인), `docs/design/` 브랜드, `web/src/styles/tokens.css`(색), 로그인 메일 디자인(아래).

## 할 일
1. **제목에 앱 이름과 사건**:
   - 열림 실패 `[쉽앤핑] {앱}에서 실패가 늘었어요`, 느림 `[쉽앤핑] {앱}이(가) 느려졌어요` → 받침 처리 대신 `[쉽앤핑] {앱} · 느려졌어요` 같은 조사 없는 형식도 가능(자연스러운 쪽 선택),
   - 더 나빠짐 `[쉽앤핑] {앱} · 문제가 더 커졌어요`, 해결 `[쉽앤핑] {앱} · 문제가 해결됐어요`, 다이제스트 `[쉽앤핑] 모아 둔 알림 N건이에요`.
   - 앱 이름은 사용자 입력이다: 줄바꿈·제어문자 제거, 40자 넘으면 자르고 `…`. 앱 이름을 못 얻으면 지금 제목 유지.
   - RPC가 앱 이름을 안 주면 마이그레이션으로 반환 필드만 추가(새 타임스탬프 파일, 기존 파일 수정 금지, 권한은 기존과 동일하게 service_role만).
2. **HTML 메일 + 텍스트 함께**: Resend 요청에 `html`과 `text` 둘 다. 텍스트판은 지금 문장 + 앱 이름 + 주소(메일 앱이 HTML을 못 볼 때).
3. **HTML 디자인 = 로그인 메일과 같은 틀** (Supabase 인증 메일 템플릿, 이미 운영 중):
   - 표(table) 레이아웃, 가로 최대 480px, 가운데, `word-break:keep-all; overflow-wrap:anywhere`, 시스템 한글 글꼴.
   - 맨 위 양 그림 64px: `https://raw.githubusercontent.com/ship-and-ping/ship-and-ping-backend/main/docs/design/brand/ship-and-ping-sheep.png`, 민트 테두리 원형(색은 tokens.css의 민트).
   - 큰 제목(사건 한 줄), 그 아래 작은 회색 줄 `{앱} · {기능 이름}`. 기능이 `기타`면 `기타 (따로 지켜보지 않는 기능 묶음)`.
   - 숫자 상자: 실패 `최근 30분 동안 9건 중 9건 실패`, 느림 `평소 x초 → 최근 y초`, 해결 `새 버전에서 5번 연속 성공했어요`.
   - 라벤더 버튼 `쉽앤핑에서 자세히 보기` → 지금 링크(문제 화면). 긴 주소 노출 금지(버튼 아래 작은 글씨로 "버튼이 안 눌리면" 링크 하나만).
   - 마지막 안내 한 줄: 열림·더 나빠짐 → `자세히 보기에서 AI에게 고쳐 달라고 할 요청문을 복사할 수 있어요.` 해결 → `따로 하실 일은 없어요.`
   - 바닥 회색: `이 메일은 쉽앤핑 알림 설정에 따라 보냈어요. 알림은 앱 설정에서 끌 수 있어요.`
   - 다이제스트는 같은 틀에 사건 목록(최대 10줄) + 버튼 하나(앱 목록).
4. **보안**: 앱 이름·기능 이름·버전 등 모든 끼워 넣는 값은 HTML 이스케이프(`& < > " '`). 링크는 서버가 만든 `WEB_ORIGIN` 기준 주소만. 기존 `mask` 그대로 유지. 오류 문구·키·요청 내용은 메일에 넣지 않는다. 슬랙 메시지는 바꾸지 않는다(앱 이름 추가 정도만 허용).
5. **판정 로직(evaluate_all 등)은 건드리지 않는다.** 지금 운영에서 알림 시험 중이다.

## 테스트 먼저
`notify.rs` 단위 테스트: 제목 4종+다이제스트, 앱 이름 제어문자·길이 자르기, HTML 이스케이프(`<script>` 앱 이름), `기타` 설명 문구, 텍스트판에 주소 포함·HTML판에 긴 주소 본문 노출 없음, Resend payload에 html·text 둘 다. 변형 검사: 이스케이프를 빼면 테스트가 실패하는지 확인.

## 고칠 것 (다른 Codex 세션 검수 결과)
1. [중간] `worker/src/notify.rs:138` — 기타 설명 문구를 **기능 이름이 "기타"인지로** 판단해서, 사용자가 일반 기능 이름을 "기타"로 지으면 개별 기능도 "따로 지켜보지 않는 기능 묶음"으로 잘못 표시된다. 묶음 여부는 이름이 아니라 **실제 묶음 기능 식별자**(features.method='*' / route='*' 등 DB에서 오는 값)로 판단. 알림 꺼내기 RPC가 그 값을 안 주면 새 마이그레이션으로 반환 필드 추가(기존 파일 수정 금지, 권한 동일). 테스트: 이름 "기타"인 일반 기능 → 설명 없음, 묶음 기능 → 설명 있음.
2. [낮음] `notify.rs:384` 다이제스트 테스트에 특수문자(`<script>&"'`) 앱·기능 이름을 넣어 233행 개별 이스케이프가 빠지면 실패하게. 변형 검사로 확인.
3. [낮음] `notify.rs:420` 미리보기 스냅샷 비교가 CRLF 체크아웃에서 깨진다 — 비교 전 줄바꿈 정규화하거나 `.gitattributes`로 미리보기 HTML을 `eol=lf` 고정.
