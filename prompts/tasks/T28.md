명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.
동시에 T24(PR #23)가 정제 규칙(`worker/`, `supabase/`, `web/src/normalize.ts`·`display*`·`issue-prompt.ts`, 시험표)을 고친다 — 그 파일들은 건드리지 않는다. 네 범위: `web/qa/`, `docs/design/qa/`, `docs/design/screens/`(새로), `README.md`의 화면 절, `prompts/tasks/T28.md`, 위임 로그 T28 행.

## 할 일
1. `web/qa/`(D6에서 만든 Playwright·가짜 데이터 도구)를 최신 화면에 맞춘다 — T21 앱 설정(S10)·내 계정(S11, 탈퇴 확인·진행·실패·완료), T22 로그인(이메일·비밀번호/메일 링크)·가입·비밀번호 찾기·재설정, T26 비밀번호 변경 본인 확인 번호 입력이 빠졌으면 장면과 가짜 데이터를 추가.
2. `npm run qa:shots`로 **최신 main 전체 화면**을 PC 1440(밝게)·휴대폰 390(밝게) 두 조건으로 찍어 `docs/design/screens/`에 흐름 순서 번호를 붙여 저장(JPG 품질 80, 장당 500KB 이하). 소개 → 로그인 → 앱 등록 → 연결 → 첫 기록 대기 → 앱 홈(정상) → 문제 상세(실패·느림) → 해결됨 → 깊게 보기 → 알림 설정 → 앱 설정 → 내 계정.
3. `README.md`에 '화면 모음' 절: 흐름 순서대로 PC 화면 썸네일과 한 줄 설명(쉬운 한국어), 휴대폰 화면은 링크. 기존 절(실행 방법·고른 메뉴 표·AI 사용 지도)은 고치지 않는다.
4. 찍으면서 보인 깨짐(넘침·겹침·한 글자 줄·빈 화면)은 고치지 말고 PR 본문 '발견'에 표로(화면·조건·증상).
5. 이 지시문을 `prompts/tasks/T28.md`로, 위임 로그 T28 행.
