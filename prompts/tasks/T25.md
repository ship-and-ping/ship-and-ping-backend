## 만들 것
1. **Worker 운영 설정**: `wrangler.toml`의 production 환경(이름, Cron 매분 `evaluate_all`·하루 `cleanup_daily` 연결 확인, 호환 날짜, 무료 플랜 한도 안), 필요한 비밀 **이름 목록**(Supabase URL·서버 키·Resend·Slack OAuth 등 — 값 없음). `workers.dev` 무료 주소 기준.
2. **웹(Pages) 설정**: SPA 새로고침 라우팅(`_redirects`), 보안 헤더(`_headers`: CSP — Supabase·Worker 주소만 connect-src, frame-ancestors none, Referrer-Policy, Permissions-Policy 등), 빌드 명령·출력 폴더, 환경 변수 이름.
3. **배포 워크플로**: 수동 실행(`workflow_dispatch`)만, 액션은 커밋 SHA 고정, 비밀은 GitHub 비밀 이름만 참조. main push 자동 배포는 넣지 않는다.
4. **`docs/deploy.md`**: 사용자가 따라 할 순서 — Cloudflare 계정·API 토큰 권한(최소 권한) → GitHub 비밀 등록 → Worker 배포 → Pages 배포 → Supabase Auth Site URL·리디렉트(`/login`·`/reset-password`)·메일 양식 → 웹 `VITE_INGEST_URL`을 Worker 주소로 → 확인 체크리스트(첫 기록 도착, 탈퇴, 알림 시험, C5 CPU 실측 방법) → 되돌리기(이전 배포로 롤백). 사람이 해야 하는 단계는 표시.
5. 로컬에서 `wrangler deploy --dry-run`(npx 고정 버전)과 웹 빌드로 설정이 맞는지 확인(로그인 없이 되는 범위).
6. 이 지시문을 `prompts/tasks/T25.md`로 복사.
