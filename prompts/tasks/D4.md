# 쉽앤핑 D4 — PC 우선 화면과 소개 페이지

## 바꾼 이유

사용자 지적(2026-11-25, 그대로): "근데 이거 웹페이지인데 앱만 너무 만든거 아니야?"
D1~D3은 휴대폰 화면을 기준으로 그리고 PC는 일부만 그렸다. 쉽앤핑은 웹페이지이고 사용자는 앱을 만들고 배포하는 PC 브라우저에서 주로 쓰므로, 사용자가 "A"(PC 우선으로 다시 그리고 소개 페이지 추가)를 골랐다. 방향(시안 C + 양 가볍게)·토큰·문구는 그대로 둔다.

## 지시문 원문 (2026-11-25, Orca 매니저)

사용자 지적(2026-11-25, 그대로): '근데 이거 웹페이지인데 앱만 너무 만든거 아니야?' → 사용자 결정: PC 우선으로 다시 그리고 소개 페이지 추가('A').
origin/main에서 새 브랜치 docs/D4-desktop을 만들고 새 PR을 여세요. 방향(C + 양 가볍게)·토큰·문구는 그대로.
1. 기준 화면을 PC 브라우저로: 브라우저 창 프레임(주소창 포함) 1440×900 기준, 1280에서도 확인. 구조는 왼쪽 메뉴(내 앱 / 알림 설정 / 내 계정, 맨 아래 로그아웃) + 오른쪽 본문(최대 폭 지정). 앱을 고르면 앱 안 메뉴(홈·기능·문제·설정). 맨 위 큰 문장 카드와 양 아바타는 본문 맨 위.
2. S1~S11 전부 PC 화면(밝은·어두운). S4·S5·S7·S11은 로딩·빈 화면·오류 상태도 PC. 요청문 미리 보기·복사처럼 PC에서 넓게 쓰는 곳은 넓은 화면에 맞게(예: 미리 보기 옆에 단계 안내).
3. 소개 페이지(새 S0, 로그인 전 첫 화면): 한 문장 소개(바이브 코딩으로 앱을 낸 사람을 위한 관리형 모니터링), 문제 공감(사용자 연락이 와야 아는 문제), 하는 일 3가지(어디서 막혔나·평소보다 느려졌나·고쳐졌나), 연결 3단계(요청문 복사 → 코딩 AI에 붙여넣기 → 배포), 실제 화면 예시(앱 홈 카드), 슬랙·이메일 알림 예시, 무료 베타 안내, [시작하기]·[로그인]. 가격·숫자 주장·과장('최고·유일')·지어낸 후기 금지. PC와 휴대폰 둘 다.
4. 휴대폰 화면은 지금 것을 반응형 기준으로 두고, S0만 휴대폰 새로.
5. design-system.md: 화면 너비 기준(PC ≥1024, 태블릿 640~1023, 휴대폰 <640), 왼쪽 메뉴·본문 최대 폭·그리드 규칙, 넓은 화면 표·목록 규칙, 키보드 이동 순서. monitoring-service-ux.md: 사용 환경 가정을 'PC 브라우저 주 사용, 알림 받으면 휴대폰으로 확인'으로 고치기. 기능명세서 3장에 S0 소개 페이지 절, version 1.2.
6. final/index.html에서 PC·휴대폰 전환해서 넘겨 보기.
7. 기록: prompts/tasks/D4.md(바꾼 이유: 사용자 지적 그대로), 위임 로그 D4 6칸.
