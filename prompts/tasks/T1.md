# 쉽앤핑 T1 — 레포 뼈대·제출 산출물 뼈대·CI

너는 Orca 작업 에이전트다. 새 작업 폴더(워크트리)에서 일하고, 끝나면 PR까지 만든다. **머지하지 않는다.**

## 먼저 읽기 (전부)
- `PRD.md` (특히 맨 위 v1.1 바뀐 점, 8장 결정 현황, 10장 제출 산출물)
- `docs/specs/2026-11-24-ship-and-ping-feature-spec.md` (0장 결정, 1장 구조, 10장 완료 조건)
- `docs/plans/2026-11-25-ship-and-ping-plan.md` (레포 구조, 작업 목록)
- `db.md`, `docs/위임로그/김태형.md`, `prompts/`

## 할 일 (맡은 파일만)
1. `AGENTS.md` — 이 레포에서 코딩 AI가 지킬 규칙:
   - 레포 구조(`worker/` Rust Cloudflare Workers, `supabase/`, `web/` React, `examples/`, `docs/`, `prompts/`)
   - 명령(아직 없는 것은 "T2/T3/T5에서 추가"라고 적기)
   - 금지: 비밀값(키·webhook·DB 비밀번호·`sb_secret_`·`.dev.vars`) 커밋, 개인정보 수집(기능명세서 4.2), 승인 우회 플래그, main 직접 push
   - 커밋 형식 `타입: 내용`(feat, fix, docs, test, chore, refactor), 브랜치 `타입/T번호-내용`
   - 작업이 끝날 때마다 `docs/위임로그/김태형.md`에 6칸(목표·프롬프트·결과·검증·수정·배운 점) 표 추가, 맡은 지시문은 `prompts/tasks/`에 저장
   - 판단 기준 문서 순서: PRD.md → 기능명세서 → db.md
2. `CLAUDE.md` — 첫 줄 `@AGENTS.md`, 그 아래 "Claude Code에서만" 짧은 메모(리뷰는 reviewflow).
3. `README.md` 뼈대 (한국어):
   - 한 줄 소개, 브랜드(이름·색 3개·마스코트 설명)
   - 실행 방법: 구성 요소별 소제목만 두고 "T2·T3·T5 완료 후 채움"
   - **고른 메뉴 표**: PRD 8장 결정 현황 + v1.1 바뀐 점을 "고른 것 / 다른 선택지 / 고른 이유" 3열 표로 (Q1~Q11, D1~D4)
   - **AI 사용 지도**: 단계별(기획 PRD, 조사, 기능명세서, 레포 뼈대 T1, 이후 T2~T11 예정) "어느 AI / 맡긴 일 / 사람이 한 일" 표. 지금까지 사실: 기획·조사·명세서는 Claude Code(매니저)가 썼고 사람이 질문에 답하며 방향을 바꿈(관리형 서비스, Rust, 앱 전체 감시), T1부터 구현은 Codex, 검증은 Claude(reviewflow)
   - 문서 지도: PRD.md, 기능명세서, db.md, prompts/, docs/위임로그/
4. `prompts/README.md` — 버전 규칙(v1·v2는 매니저 요청, `prompts/tasks/T번호.md`는 작업 지시문, 각 파일에 "바꾼 이유" 칸). 이 지시문 전체를 `prompts/tasks/T1.md`로 저장.
5. 폴더 자리: `worker/README.md`, `supabase/README.md`, `web/README.md`, `examples/README.md` — 각 1~3줄로 무엇이 들어갈지(어느 작업에서).
6. `.gitignore` — Rust `target/`, `node_modules/`, `dist/`, `.wrangler/`, `.dev.vars`, `.env*`(단 `.env.example` 허용), `supabase/.temp/`, OS 파일.
7. `.github/workflows/ci.yml` — 이름 `ci`, push(main)·pull_request에서:
   - `secrets` 작업: gitleaks로 비밀값 검사(공식 gitleaks/gitleaks-action 또는 gitleaks CLI 직접 설치; 유료 라이선스가 필요한 방식이면 CLI 설치 방식으로). 무료여야 한다.
   - `docs` 작업: 위 산출물 파일(PRD.md, README.md, AGENTS.md, CLAUDE.md, db.md, prompts/, docs/위임로그/김태형.md)이 있는지 확인하는 짧은 셸 스크립트 `scripts/check-deliverables.sh`.
   - 나중 작업이 `worker`·`supabase`·`web` 테스트 작업을 추가할 자리를 주석으로.
8. `docs/위임로그/김태형.md` 끝에 "## 4. T1 레포 뼈대" 6칸 표 추가(배운 점은 "(직접 작성)").

## 하지 말 것
- PRD.md·기능명세서·db.md 내용 수정 금지(오타를 발견하면 PR 본문에 적기만).
- 실제 Rust·React·Supabase 코드 작성 금지(다음 작업).
- 비밀값·개인 이메일을 파일에 쓰지 않는다.

## 확인
- `bash scripts/check-deliverables.sh` 통과.
- 로컬에 gitleaks가 있으면 `gitleaks detect --no-banner` 통과(없으면 PR의 CI 결과로).
- 변형 검사: `docs/위임로그/김태형.md`를 잠시 다른 이름으로 바꾸면 스크립트가 실패하는지 확인 후 되돌리기.

## PR
- 브랜치 `chore/T1-repo-skeleton`, 커밋 `chore: …`/`docs: …`.
- PR 제목 `chore: T1 레포 뼈대와 제출 산출물 뼈대`, 본문: 만든 파일 목록, 확인 결과, 남은 것.
- `gh pr checks`로 CI 결과까지 확인. **머지 금지.**

## 보고 (마지막 메시지)
PR 주소, 바뀐 파일, 확인 결과(명령과 결과), CI 결과, 막힌 점.
