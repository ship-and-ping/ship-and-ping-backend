## 1단계 — 성능 개선 (T2 검증자 분석, 이것부터 하고 재측정)
현재 네이티브 64KB·100건 중앙값 3.472ms / 최대 6.496ms (CPU 한도 10ms, wasm은 더 느림).
1. 모든 `\b`를 `(?-u:\b)`(ASCII 경계)로 — 유니코드 경계 때문에 lazy DFA가 비ASCII에서 PikeVM으로 떨어짐.
2. 짧은 접두사 규칙을 별도 정규식 `(?i:sk_|pk_|rk_)[A-Za-z0-9_]{16,}`로 빼고 `find_iter`로 앞 바이트(ASCII 영숫자 아님)를 코드에서 검사, 주 정규식은 캡처 없이 `regex::NoExpand`로 치환.
3. `normalize`에 빠른 경로: `unicode_normalization::is_nfkc_quick`이 Yes이고 제거·줄바꿈 대상 문자가 없으면 원문을 빌려 씀.
4. records를 `Vec<Box<RawValue>>`로 받아 기록별 한 번만 파싱, `#[serde(flatten)]` 이중 버퍼링 제거(기록 단위 dropped 유지).
5. 주소 조각은 `_ = @ %` 또는 비ASCII가 있을 때만 PRIVATE 검사.
6. 벤치를 ASCII 전용·한글 포함 두 가지로 나눠 재측정하고 `wrangler dev` wasm 시간도 BENCH.md에 기록. 가림 결과는 공통 시험표로 동일함을 확인(동작 변화 없음).

## 2단계 — 수집 Worker 완성 (테스트 먼저)
1. **키 확인**: 수집 키 해시 → 앱 찾기를 메모리 캐시(5분)로. 캐시는 '형식·앱 찾기' 용도이고 **저장 여부는 DB(lock_key)가 매 묶음 결정**(명세 6.0·9장). 폐기·만료 키는 DB가 PT401 → 401.
2. **한도(5.4)**: 앱당 1분 20묶음·하루 2,000묶음을 isolate 메모리 카운터로 대략 세고 넘으면 429 + `Retry-After`. 정확한 집계는 DB(나중). KV 쓰기 한도(하루 1k) 때문에 KV 카운터는 쓰지 않는다.
3. **`POST /v1/feature-map`(5.2)**: 수집 키로, `[{route, method, name}]` 최대 200개, 이름·route 정제(공통 가림), `suggest_feature_map` RPC 호출. 응답표는 ingest와 같은 원칙.
4. **CORS**: 브라우저 전송용 `OPTIONS` 사전 요청, `Access-Control-Allow-Origin: *`(키로만 판단), 허용 헤더 `Authorization, Content-Type`. `navigator.sendBeacon` 대비 `Content-Type: text/plain`의 JSON 본문도 받기(헤더 대신 본문 `key` 필드 허용 여부는 보안 검토 후 PR 본문에 의견 — 기본은 헤더만).
5. **source=server 규칙(매니저 결정)**: 브라우저 키로 온 `source=server` 결과는 묶음 400이 아니라 **그 기록만 dropped**.
6. 운영 안전: `SUPABASE_URL`·`SUPABASE_SECRET_KEY` 없으면 503(INGEST_DRY_RUN=true일 때만 202) 유지. 응답표 밖 코드 금지.
7. 테스트: 캐시 만료·폐기 키 401, 한도 429·Retry-After, feature-map 성공·검증 실패·200개 초과, CORS 사전 요청, text/plain 본문, source=server dropped, 공통 시험표 계속 통과.
8. `worker/README.md`·BENCH.md 갱신, 이 지시문을 `prompts/tasks/T4.md`로.

## 지킬 것
- 명령은 경로를 그대로 써서 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 편집 도구로.

- 쓰기·커밋이 막히는 환경이면 즉시 오류 원문과 함께 보고하고 멈춘다.
