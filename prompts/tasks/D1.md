## 할 일
### 1. 사용자 흐름 문서 `docs/monitoring-service-ux.md`
- 대상·목표·사용 환경(평소 PC, 알림을 받으면 휴대폰 슬랙 링크로 먼저 엶 — **가정**으로 표시)
- 핵심 흐름: 문제 발견(알림) → 쉬운 설명 → AI에 보낼 내용 복사 → 업데이트 후 해결 확인
- 첫 사용 흐름: 가입 → 앱 등록 → 연결 요청 복사 → 첫 기록 도착 → 기능 이름표 확인
- 화면별(S1~S10) 로딩·빈 화면·오류·완료 상태와 복구 경로, 막힐 수 있는 지점
- 아래 UX 체크리스트로 스스로 점검한 결과

### 2. 시안 3개 `docs/design/mockups/`
- 서로 **방향이 다른** 3개(예: 차분한 상태 보드 / 마스코트가 말 거는 친근한 방식 / 큰 숫자·문장 중심의 알림 카드 방식 — 예시일 뿐, 스킬로 판단).
- 각 시안마다 흐름 순서대로 화면 3장:
  ① S4 연결 — "기록이 도착했어요. 기능 8개를 찾았어요" + 기능 이름표 확인
  ② S5 앱 홈 — 열린 문제 1개("분석이 느려졌어요. 평소 1.1초 → 최근 30분 3.4초 (24건)") + 기능 목록
  ③ S7 문제 상세 — [AI에 보낼 내용 복사] + 업데이트 후 해결 확인("업데이트 후 분석 15건 모두 평소 속도로 끝났어요")
- 각 화면을 **휴대폰 화면 전체**(기기 프레임·상태 바·헤더까지, 일부만 잘라 그리지 않음)와 **PC 브라우저 화면**으로, **밝은·어두운** 둘 다.
- 각 시안 설명: 콘셉트 한 줄, 움직임(무엇이 언제 어떻게), 디자인 값(색 토큰, 글꼴, 글자 크기 단계, 간격, 모서리, 그림자), 난이도·위험, 추천 순위와 이유.
- 형식: 시안마다 하나의 **자체 완결 HTML**(`option-a.html`, `option-b.html`, `option-c.html` — 외부 CSS/JS 없이 인라인, 이미지는 base64 data URI, 글꼴은 Google Fonts 링크만 허용) + 세 시안을 한 화면에서 나란히 비교하는 **`compare.html`**(역시 자체 완결, 밝은/어두운 전환 버튼, 시안별 설명 표 포함). 매니저가 compare.html을 사용자에게 웹페이지로 보여 준다.
- 가능하면 화면 캡처 PNG도 `docs/design/mockups/png/`에(브라우저 도구가 없으면 생략하고 보고).
