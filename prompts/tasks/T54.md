# 쉽앤핑 T54 — 연결 요청문 확장: 앱 프로필 + 서버 기록(1분) + 살아 있음 신호 + 서버 패널

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더(origin/main)에서 PR까지. **머지 금지.** Windows — 웹 로컬, Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.
동시에 도는 작업: T49(PR #46 푸시·data.ts·App.tsx·알림 설정), T52(PR #48 issue-prompt.ts·incident_context), T55(문제 종류), T56(MCP). **새 파일 위주로**, 겹치는 파일은 최소 수정.

## 사용자 결정 (2026-11-28)
"처음에 앱을 등록하고 AI 요청문에 쉽앤핑이 지금 모르는 것들에 대한 정보를 받아 볼 수 있게" — 연결 요청문으로 AI가 아래를 설정하게 한다. 사용자는 아무것도 몰라도 된다. 비용 0원.

## 1. 앱 프로필 (연결 때 1회 + 바뀌면 갱신)
- 수집 API `POST /v1/profile`(앱 키 인증, 기존 수집 키와 같은 방식): **고정 스키마만** — 언어·프레임워크(짧은 이름), 호스팅 제공자·요금제 등급(free/paid/unknown)·CPU 코어 수·메모리(GB), DB 종류(postgres/mysql/sqlite/mongo/none/other), 기능별 외부 서비스 종류(지도·결제·AI·메일·저장소·기타 + 서비스 이름 40자), 배포 방법(짧은 이름), 되돌리기 방법(한 줄 80자), 서버 지표 보는 법(한 줄 120자).
- **보안**: 모든 문자열 길이 제한, URL·이메일·IP·키·토큰·연결 문자열 모양이면 거부(기존 가림 규칙 재사용 + 허용 문자), 알 수 없는 필드 거부, 앱당 1행(덮어쓰기), 변경 이력은 최근 5개만. 앱 설정 화면에서 보기·지우기.

## 2. 서버 기록 (1분마다, 숫자만)
- 기존 수집 배치에 선택 필드 `resources`: process_cpu_pct, system_cpu_pct, steal_pct, mem_used_pct, gc_pause_ms(1분 합), busy_threads/event_loop_lag_ms, db_pool_in_use/db_pool_max(가능하면). 범위 검증(0~100 등), 없으면 생략 허용.
- 요청별 선택 필드 `db_ms`, `external_ms`(합계만, 대상 이름 없음) → 기능별 5분 버킷에 합계·건수로.
- 살아 있음 신호: 배치가 없더라도 1분마다 `resources`만 보내면 됨. 평소 기록이 오던 앱이 **10분 이상 끊기면** 새 문제 종류 `silent`("기록이 끊겼어요")를 열고 알림(평소 범위: 최근 7일 같은 시간대 기록이 있던 앱만, 오탐 방지). 재개되면 해결.
- 저장: 새 테이블(1분 해상도 7일 보관, 이후 1시간 요약), RLS 앱 주인만, 앱당 분당 1행 상한·초과 무시.

## 3. 연결 요청문·추가 연결 요청문
- `buildConnectPrompt`에 1·2를 설정하는 단계 추가(언어별 예시: Node·Java/Spring·Python·Go 최소 코드, 표준 라이브러리 우선). 비밀값을 프로필에 넣지 말라는 문장.
- 이미 연결된 앱용 **"추가 연결 요청문"**(앱 설정): 키 미포함, 기존 연결은 건드리지 말고 프로필·서버 기록만 추가하라는 내용.

## 4. 화면
- 앱 홈·기능 상세의 Grafana식 패널 그리드에 **서버 패널**(CPU·steal·메모리·GC 시계열, 공유 십자선 기존 규칙), 기록이 없으면 "추가 연결 요청문으로 서버 상태도 볼 수 있어요" 안내. 문제 상세에 사건 구간 서버 기록 요약.
- 문제 요청문에는 T52 쪽이 프로필·서버 기록을 쓸 수 있게 **읽기 함수/RPC만** 제공(issue-prompt.ts 문구 수정은 T55 몫 — 필요한 데이터 필드를 PR 본문에 명시).
