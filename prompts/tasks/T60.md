# 쉽앤핑 T60 — 전체 디자인 다시 보기 (검토 보고서만, 코드 수정 금지)

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일한다. **이번 작업은 평가·우선순위 보고서와 캡처만** 만든다. 앱 코드는 바꾸지 않는다. PR은 문서·캡처만, 머지 금지. Windows — 웹 실행·캡처는 로컬.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 사용자 요청 (2026-11-28)
"전체적으로 디자인 다시 봐줘". 직전 지적: 요약 카드 미니 그래프에 기준선·십자선 없음(→ T57 진행 중), 로그아웃 안내가 왼쪽 위에 잘린 흰 상자로 헤더를 밀어냄·정적인 로그인 화면(→ T58 진행 중). 사용자는 "레퍼런스 수준의 완성도"를 원한다(맨날 보면 뭔가 다르고 아쉽다). 대시보드 방향은 Grafana 느낌으로 확정, 소개 페이지는 홈페이지 효과 12가지(`docs/homepage-effects-12.md`) 기준. 발표가 2일 뒤라 **발표 전에 고칠 것 / 뒤로 미룰 것**을 나눠야 한다.

## 쓸 도구 (이 기기에서 실제로 쓸 수 있는지 먼저 확인, 새로 설치 금지, 쓴 것·안 된 것 보고)
- `impeccable`(critique/audit) — 중심. 화면별 점수·문제·고칠 순서.
- `ui-ux-pro-max` — 여러 화면 공통 규칙(간격·글자 단계·색·컴포넌트 일관성).
- 차트는 dataviz 원칙(축 하나, 옅은 점선 기준선, 단일 시리즈 범례 없음, 툴팁, 글자는 텍스트 색 토큰).

## 볼 화면 (전부, PC 1440px 우선 + 390px, 밝은·어두운)
소개 페이지 → 회원가입·로그인·비밀번호 찾기 → 앱 등록·연결 요청문 → 앱 홈(요약 카드·사용 흐름) → 기능 목록 → 기능 상세(그래프) → 문제 화면(AI 요청문·복사) → 알림 설정(푸시·메일) → 홈 화면 앱(PWA) 첫 화면 → 로그아웃 안내·빈 화면·로딩·오류 상태.
- 운영 사이트(https://ship-and-ping.pages.dev)는 로그인 없이 보이는 화면만. 로그인 뒤 화면은 로컬 실행 + 예시 데이터(`web/qa/shots.mjs` 등 기존 캡처 도구)로. **운영 계정에 로그인하거나 비밀번호를 입력하지 않는다.**

## 기준
- 디자인 가이드 UX 체크리스트: 사용자 목표, 정보 구조, 작업 흐름, 입력과 안내, 로딩, 빈 화면, 오류, 완료, 접근성(키보드·포커스·대비 4.5:1·동작 줄이기·큰 글자).
- 사용자는 개발을 모르는 바이브코딩 메이커 — "지금 괜찮은지 → 왜 → 뭘 하면 되는지"가 화면마다 같은 순서로 읽히는지. 문제 알림을 받고 **AI 요청문을 복사하기까지 걸리는 탭 수·시간**이 가장 중요.
- 레퍼런스 대비 완성도: Grafana(대시보드), 토스·PostHog·Plausible(카드·숫자·여백), 화면마다 "레퍼런스 캡처 | 지금" 나란히 놓고 간격·글자 단계·모서리·그림자·선 굵기를 **측정해서** 차이를 적는다. 로고·문구·이미지 복사 금지.
- 화면 사이 일관성: 버튼·카드·제목·안내 상자·토스트·빈 화면 모양이 화면마다 다른 곳 목록.
