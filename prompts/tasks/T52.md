# 쉽앤핑 T52 — AI 조사 요청문 개선 (실사용 피드백 반영: 부하·동시 장애 맥락)

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더(origin/main 기준, T51 포함)에서 PR까지. **머지 금지.** Windows — 웹 로컬, Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.
T49(PR #46)가 data.ts·App.tsx·알림 설정을 바꾸는 중 — 그 파일은 최소로.

## 배경 (2026-11-27 Trova 한계 시험, Trova 매니저 피드백)
쉽앤핑 요청문을 덧붙임 없이 Codex에 넘겼더니 원인을 빗나감(실제: 무료 서버 CPU 부족·steal 68%, AI 추정: 쿼리·데이터 중복).
1. 요청문에 **요청량 변화·동시에 느려진 다른 기능** 정보가 없었다.
2. 쉽앤핑이 못 보는 클라이언트 시간 초과(약 500건)가 안 드러났다.
3. 사건 뒤의 무관한 401("23:38 UNAUTHORIZED")이 대표 오류로 보였다.
4. 버전 [가림](T51에서 해결).
5. 감지 시각(23:21:05)만 있고 첫 느린 구간 시작(23:20)이 없었다.
매니저가 같은 사건으로 손으로 만든 개선 예시는 아래 '예시'와 같다 — 이 내용을 데이터로 자동 생성하게 만든다.

## 할 일 (`web/src/issue-prompt.ts` 중심, 필요한 읽기 RPC는 새 마이그레이션·앱 주인 권한)
1. **요청량 비교**: 사건 구간 분당 요청 수 vs 평소(최근 7일, 사건·열린 문제 구간 제외) 분당 요청 수와 배수. 평소가 너무 적으면 "평소 거의 없음".
2. **동시 장애**: 같은 앱에서 사건 시작 ±10분에 열린 다른 문제(기능 이름·평소→감지·최악)를 목록으로. 2개 이상이면 판단 힌트 1번(서버 자원 한계 가능성)을 넣는다. 1개뿐이면 그 기능 코드·최근 배포를 먼저 보라는 힌트.
3. **오류 종류 정리**: 사건 시작 10분 전 ~ 사건 종료(또는 현재)만, 느림 문제에서는 4xx(401·403·404 등)를 '원인 후보'에서 빼고 "관련 없을 가능성 높은 4xx n건"으로 따로 한 줄. 5xx 0건이면 명시.
4. **시각 두 개**: 첫 느린 구간 시작(5분 버킷)과 쉽앤핑 감지 시각.
5. **쉽앤핑이 볼 수 없는 것** 고정 문단: 서버 CPU·메모리·steal·DB 연결·스레드, 클라이언트 시간 초과.
6. **판단 힌트 순서** 문단(동시 장애·요청량 폭증·5xx 없음 → 자원 한계 → 코드·설정으로 버티기 방법 → 아니면 공통 코드 → 배포 후 같은 조건 재측정), app_version 규칙 한 줄.
7. 길이: 기존 요청문보다 너무 길어지지 않게(목록은 최대 5개), 키·개인정보 미포함 유지, 기존 보안 테스트 유지.

## 예시 (같은 사건, 매니저 작성 — 문구 참고용)
"23:20(5분 구간)부터 3개 기능이 동시에 느려짐(장소·북마크·여행, 평소 0.07~0.09초 → 감지 0.6~0.7초, 최악 1.2~1.4초). 요청량 평소 분당 약 1건 → 사건 중 분당 약 1,000건. 5xx 0건, 사건 뒤 4xx 1건은 무관. 사건 직전 코드 배포 없음(재시작 버전). 쉽앤핑이 볼 수 없는 것: CPU·메모리·steal·DB 연결·스레드, 클라이언트 시간 초과. 판단 순서: 자원 한계 → 캐시·무거운 조회·연결 풀·스레드 풀 → 아니면 공통 코드 → 배포 후 같은 조건 재측정."
