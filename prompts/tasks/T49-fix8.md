# 쉽앤핑 T49-fix8 — 오프라인 강제 로그아웃 후 노출 막기 (마지막 경로)

너는 Orca 작업 에이전트(Codex)다. 기존 브랜치 `feat/T49-pwa-push`(PR #46)에 이어서 커밋. main 합치기 금지. Windows — Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 8차 지적 (중간)
오프라인에서 [그래도 이 기기에서 로그아웃]을 고르면 브라우저 구독과 서버 세션이 남을 수 있고, 재연결 뒤엔 자격이 없어 정리 불가 → 이전 회원의 새 알림이 공유 기기에 표시될 수 있음(`web/src/data.ts` 194·470·481, `20261128004902_push_cleanup_owner.sql` 8).

## 매니저 결정 — 기기 쪽에서 내용 표시를 막는다
1. 강제 로그아웃(서버 폐기 미확인) 시 서비스 워커가 읽을 수 있는 저장소(IndexedDB)에 **'잠금' 표시**를 남긴다. 서비스 워커는 잠금 상태에서 푸시를 받으면 **앱 이름·기능·숫자 없이** "쉽앤핑 알림이 있어요 — 로그인해서 확인하세요"만 표시하고, 가능하면 `pushManager.getSubscription()?.unsubscribe()`를 시도한다.
2. 다음에 누군가 로그인하면(같은 회원이든 다른 회원이든) 로그인 직후 잠금 상태의 남은 구독을 정리(해제)하고 잠금을 푼다. 새 회원은 [푸시 켜기]로 새로 등록.
3. 강제 로그아웃 확인 문구를 정확하게: "이 기기에서 알림 내용은 가려지지만, 다시 로그인하기 전까지 '쉽앤핑 알림이 있어요' 표시가 올 수 있어요."
4. 회귀 테스트(잠금 상태 푸시 → 내용 없는 표시, 재로그인 → 정리·잠금 해제) + 변형 검사. 다른 동작 변경 금지.
