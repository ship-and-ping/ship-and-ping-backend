# 쉽앤핑 T51 — 요청문 복사 찾기 쉽게 + 버전 표시 '[가림]' 고치기 + 연결 요청문에 버전 규칙

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더(origin/main 기준)에서 PR까지. **머지 금지.** Windows — 웹 로컬, Rust·DB는 CI.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.
다른 작업 T49(PR #46)가 `web/src/data.ts`·`App.tsx`·알림 설정을 바꾸는 중 — 그 파일은 꼭 필요할 때만 최소로.

## 배경 (2026-11-27 트루바 한계 시험 실사용)
1. 사용자: 문제 화면의 [AI 조사 요청문 복사]가 "위에 있어서 못찾았었어" — 앱 홈·기능 화면에서 문제를 보고도 복사 버튼을 못 찾음.
2. 문제 상세 '지금까지 흐름'·'업데이트 후 확인'에 트루바 버전이 **"[가림] (형식 확인 필요)"**로 표시됨. 트루바 app_version이 시각+UUID 형태(예 `2026-11-27T04:21:09.780Z-1d79c156-5e7e-43e2-9cc6-08b34e145f4e`)거나 커밋 해시라 비밀값 가림 규칙에 걸린 것으로 보임.
3. 트루바는 서버 재시작만으로 새 버전이 생겨, AI 수정 없이도 '해결'될 수 있었다.

## 할 일
1. **복사 버튼 찾기 쉽게**: 앱 홈 상태 요약의 열린 문제 카드와 기능 상세의 열린 문제 줄에 [AI 조사 요청문 복사] 버튼을 바로 둔다(문제 상세와 같은 요청문, 키 미포함 유지). 문제 상세에서는 버튼 옆에 "코딩 AI에 붙여 넣으세요" 한 줄과 다음 단계(붙여 넣기 → 고친 뒤 배포 → 새 버전 5번 정상이면 해결) 3단계 안내를 버튼 가까이에. 휴대폰에서는 하단 고정 버튼 유지.
2. **버전 표시**: `displayVersion` 등 가림 규칙을 점검 — git 커밋 해시(7~40자 16진수), 시각, 시각+UUID, semver 같은 **흔한 버전 형식은 가리지 않고** 짧게 보여 준다(예: `02659da`, `11/27 13:21 배포`, 긴 UUID는 앞 8자). 진짜 비밀값 형태(키 접두사, 긴 base64 등)만 가림. 요청문·메일·화면이 같은 함수 사용. 기존 보안 테스트 유지 + 새 형식 테스트.
3. **연결 요청문**(`buildConnectPrompt`)과 키 교체 요청문에 한 줄: "app_version에는 배포한 git 커밋 짧은 해시(없으면 배포 버전 번호)를 넣고, 서버 시작 시각이나 무작위 값은 쓰지 마세요 — 재시작만으로 새 버전이 되면 '해결' 판정이 틀어져요." 문서 `docs/`의 SDK 안내도 같게.
