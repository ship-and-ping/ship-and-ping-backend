# 쉽앤핑 T32 — 휴대폰에서 승인하면 PC도 로그인 (기기 간 로그인 승인)

너는 Orca 작업 에이전트(Codex)다. 새 작업 폴더에서 일하고 PR까지 만든다. **머지 금지.** 이 기기(Windows)는 Rust 테스트 실행이 막힌다 — Rust·DB 테스트는 PR CI로 확인, 웹 테스트·빌드는 로컬.
명령은 경로를 그대로 하나씩(셸 변수·명령 치환·인터프리터 한 줄 실행 금지), 파일은 Read·Write(편집) 도구로.

## 사용자 결정 (2026-11-26, 그대로)
"이거 핸드폰으로 로그인하면 컴퓨터 화면도 같이 로그인되게 해줘" → 선택지 중 **"휴대폰에서 '승인' → PC 자동 로그인"**.

## 흐름
1. PC 로그인 화면에서 메일 링크 로그인(또는 가입 확인)을 요청하면 PC가 **로그인 요청**을 만든다: Worker `POST /v1/login-requests` {email} → `{request_id, poll_secret, match_code(2자리 또는 3자리 숫자), expires_at}`. 메일 링크의 복귀 주소는 `/login/approve?req=<request_id>`. PC 화면은 "휴대폰에서 메일을 열고 '이 PC 로그인 승인'을 눌러 주세요. 확인 숫자: **27**"을 보이며 몇 초 간격으로 `GET /v1/login-requests/<id>`(poll_secret 헤더)를 확인한다.
2. 휴대폰에서 메일 링크를 누르면 Supabase가 휴대폰을 로그인시키고 `/login/approve?req=…`로 온다. 화면: "PC 로그인을 승인할까요? 요청 시각·브라우저 종류·대략 위치(국가/도시 수준, Cloudflare 요청 정보), **PC 화면의 숫자와 같은 숫자를 고르세요**(보기 3개 중 1개)". [승인]/[거절]. 같은 기기(PC)에서 링크를 연 경우는 지금처럼 바로 로그인하고 요청은 자동 완료.
3. 승인 시 휴대폰이 `POST /v1/login-requests/<id>/approve` {match_code}를 **로그인 세션(JWT)**으로 호출. Worker는 세션 사용자 이메일 = 요청 이메일, 숫자 일치, 미만료·미사용을 확인한 뒤, Supabase Admin `generate_link`(type magiclink)로 **PC용 1회용 token_hash**를 만들어 요청에 저장(암호화 또는 해시로, 평문 장기 저장 금지). 휴대폰 토큰을 PC로 넘기지 않는다.
4. PC 폴링이 승인을 보면 token_hash를 한 번만 받아 `supabase.auth.verifyOtp({ token_hash, type: 'magiclink' })`로 **PC 자신의 세션**을 만든다. 받은 즉시 서버 쪽 값은 삭제(1회용).

## 보안 (필수, 테스트로 고정)
- 요청 유효 10분, 1회용, 승인·거절·만료 후 재사용 불가. poll_secret은 PC만 가짐(서버엔 해시만), 폴링 응답에 이메일·토큰 외 정보 없음.
- **피싱 방지**: 공격자가 자기 PC에서 피해자 이메일로 요청을 만들고 피해자가 무심코 승인하는 경우를 막기 위해 숫자 맞추기 필수 + 승인 화면에 요청 PC 정보 표시 + "직접 요청하지 않았다면 거절" 안내. 숫자 3번 틀리면 요청 폐기.
- 요청 생성·폴링·승인 모두 요청 수 제한(이메일·IP 기준). 존재하지 않는 이메일이어도 같은 응답(계정 존재 비노출).
- 서버 비밀 키는 Worker 밖으로 나가지 않음, 응답·로그에 token_hash 출력 금지(전달 응답 1회 제외).
- 거절하면 PC에 "휴대폰에서 거절했어요" 표시.

## 만들 것 (테스트 먼저)
- DB 새 마이그레이션(20261126400000번대): `private.login_requests`(id, email, poll_secret_hash, match_code_hash, status, attempts, token_hash 암호/보관, client_info, created_at, expires_at), 정리(cleanup_daily에 만료분 삭제), service_role 전용 함수. 정제·권한·search_path 규칙 동일.
- Worker 엔드포인트 3개(+ CORS는 WEB_ORIGIN만), Rust·HTTP 테스트.
- 웹: 로그인·가입 대기 화면(숫자·폴링·만료·거절·재요청), `/login/approve` 화면, 같은 기기 처리. 기존 메일 링크·비밀번호 로그인 회귀 없음. 모바일(390)·PC(1440) 캡처(`npm run qa:shots`)를 `docs/design/screens/`에 추가.
- 메일 양식: 로그인·가입 확인 메일 문구에 "이 메일을 휴대폰에서 열면 PC 로그인을 승인할 수 있어요" 한 줄(`supabase/templates/`).
- 문서: 기능명세서 S1 흐름·보안 절(버전 올리고 사용자 결정 인용), UX 문서 상태 표, `docs/deploy.md`(운영 적용 순서: 마이그레이션 → Worker → Pages), `prompts/tasks/T32.md`, 위임 로그 T32 행.
